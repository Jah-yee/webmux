## Context

动机与行为以 `proposal.md` 和 `specs/terminal-draft-scratch/spec.md` 为准。现有草稿已经覆盖单会话当前正文、未确认提交、生成代际和本机恢复；本变更在其旁边增加多条暂存，不能改变显式发送和输入路由。

现有约束：

- `DraftStorage` 以 `webmux.draft.<sessionId>` 为一个会话一条记录，`load/save/remove/keep/count` 都按这个粒度工作。
- `TerminalDraft` 由 `App.svelte` 生命周期拥有，当前草稿正文、提交状态和恢复状态由 `createTerminalDrafts` 维护。
- 上传、粘贴、代码引用和快捷指令通过 `DraftOperation` 绑定 `{sessionId, entryIdentity, draftEpoch}`，异步结果只能进入原始条目。
- 草稿面板只在草稿模式开启时挂载；顶栏按钮在关闭时仍需显示隐藏草稿和暂存状态。
- 可见 UI 变更需要真实实现截图；本变更不修改服务端和发送协议。

## Goals / Non-Goals

**Goals:**

- 每会话保留一份当前草稿和多条暂存，两边独立编辑。
- 暂存只在用户显式取用时进入当前草稿，绝不自动发送。
- 旧单草稿无需迁移即可继续恢复；旧版本回退时不删除暂存。
- 存储禁用、损坏、过期或超额时降级到页面内存，并给出可操作提示。
- 保持现有提交锁定、generation 绑定和异步输入身份边界。

**Non-Goals:**

- 不做自动发送队列、任务执行队列或跨设备同步。
- 不把“已写入终端”解释成 agent 已执行，也不增加可靠回合协议。
- 不实现系统分享导入、语音转写、审批/问答卡片或结构化对话阅读。
- 不把暂存写入服务端、URL、日志或遥测。

## Decisions

### 1. 独立键和 v1 结构，不做当前草稿迁移

当前草稿继续使用 `webmux.draft.<sessionId>` 的 v1 记录。暂存使用 `webmux.scratch.<sessionId>`：

```text
{ v: 1, sessionId, generation, entries: [{ id, text, createdAt, updatedAt }], savedAt }
```

原因：

- 旧版应用只扫描 `webmux.draft.` 前缀，回退时不会删除 `webmux.scratch.`。
- 旧单草稿保持原结构恢复，不会因新 schema 不匹配被当作损坏记录清理。
- 当前草稿和暂存可以分别计算容量、过期和保存失败状态。

暂存 ID 使用 `crypto.getRandomValues` 生成十六进制随机值；`crypto.randomUUID` 在非安全上下文不可用。schema 校验 8–64 位 `[A-Za-z0-9_-]` 并拒绝重复 ID。

### 2. 容量、保留期和清理

首版限制：

- 每会话最多 20 条；
- 单条最多 20,000 字符；
- 每会话合计最多 100,000 字符；
- 沿用当前草稿的 7 天保留期，以该会话暂存记录的 `savedAt` 计时。

模型在新增和编辑时先检查限制，超限操作不修改现有条目并返回可显示的原因。存储层再次校验，损坏、过期或重复 ID 的记录在读取时拒绝并清理；超限或写入失败的保存保留上一次成功记录，避免一条过大暂存清空全部已保存备注。写入失败或 `localStorage` 不可用时，内存内容保留，`scratchPersisted = false`，界面显示“仅当前页面”。

`keep(sessionIds)`、`remove(sessionId)`、`clear()` 和关闭本机保存同时处理两个前缀。`count()` 继续表示“有本机当前草稿的会话数”，新增 `scratchCount()` 表示暂存条目总数，避免把会话数与条目数混在一起。

### 3. 状态模型拥有暂存，组件只调用显式操作

`TerminalDraft` 增加：

- `scratch`：暂存条目数组；
- `scratchPersisted`：当前暂存是否已写入本机；
- `scratchGeneration`：保存记录的运行代际；
- `scratchUpdatedWhileHidden`：草稿关闭期间暂存是否更新。

`TerminalDrafts` 增加：

- `addScratch(entry, text)`：新增暂存；空文本不创建。
- `editScratch(entry, id, text)`：编辑正文和修改时间，保持 ID 与顺序。
- `removeScratch(entry, id)`、`moveScratch(entry, id, delta)`：删除和排序。
- `stash(entry)`：把当前草稿转存为暂存并清空当前草稿。
- `takeScratch(entry, id, mode)`：`append` 或 `replace` 取用，成功后从暂存移除。
- `clearScratch(entry)`：清空该会话全部暂存。

所有操作校验条目身份。无提交时 `stash` 与 `takeScratch` 才可用；取用成功后如有需要会开启草稿模式，但不会调用发送、不会聚焦终端、不会改动提交状态。

### 4. 取用冲突规则

- 当前草稿为空：直接把暂存正文写入当前草稿。
- 当前草稿非空：界面询问“追加到当前草稿”或“替换当前草稿”。
- 追加：在原正文后加入一个换行分隔（原正文已以换行结尾时不重复添加），再写入暂存正文。
- 替换：先移除目标暂存，在释放出的条目空间内把当前正文转存为新暂存，再把目标正文写入当前草稿；转存失败时恢复目标条目并保持当前草稿不变。
- 当前草稿存在未确认提交：禁止转存和取用，避免把“可能已到达终端”的正文移走或覆盖。
- 取用只改变草稿正文，不自动发送，不自动聚焦终端，不改变当前代码视图。

暂存条目不会被上传、粘贴、代码引用或快捷指令直接写入；这些异步输入继续只写当前草稿。这样现有 `{sessionId, entryIdentity, draftEpoch}` 身份边界无需扩展。

### 5. 生成代际与恢复

暂存按会话 ID 保留，不沿用旧实例的提交状态。加载时恢复 `entries` 和保存时的 `generation`；绑定新的运行代际后，如果两者不同，暂存面板提示“来自较早的会话实例”，但不自动发送、不清空。用户取用或修改暂存时，记录按当前代际重新保存，提示随之消失。

认证失效仍只清内存；已保存的当前草稿和暂存会在重新认证后按原规则恢复。会话确认移除时同时清除两个键和内存状态。

### 6. 界面

- 草稿操作行增加“暂存 (N)”按钮，打开复用 shadcn Dialog 的 `ScratchPanel`；终端菜单也提供“暂存”入口，使草稿关闭时仍能查看和整理暂存。
- 面板顶部提供“将当前草稿存入暂存”和“清空暂存”。列表每条显示可编辑正文、修改时间、字符数、上移、下移、取用和删除；底部提供新建暂存。
- 草稿关闭时，顶栏“草稿”按钮显示暂存条数；从菜单新增或修改暂存会设置 `scratchUpdatedWhileHidden`，标题和无障碍状态提示“暂存已更新”，但不自动打开草稿。
- 暂存面板对未确认提交、代际不一致、容量超限和存储失败给出明确提示；不新增常驻帮助段落。
- 取用成功后关闭暂存面板，让用户看到更新后的草稿；取用不触发发送。

### 7. 设置与文档

设置页分别显示“N 个会话的草稿，M 条暂存”，关闭本机保存或清除全部内容时同时处理当前草稿和暂存。使用文档说明暂存入口、取用冲突、自动发送边界、容量和恢复规则。User Stories 新增 US-F09 并更新 US-F01、US-F03、US-F06、US-F07、US-F08 与两个索引。

## Risks / Trade-offs

- 暂存与当前草稿并存增加界面和状态复杂度 → 通过独立存储键、独立模型和显式取用入口隔离，避免影响发送路径。
- 取用“追加”需要插入换行 → 固定为一处分隔符，并在文档说明；不自动 trim 或改写正文。
- 替换时转存当前正文可能触碰容量上限 → 先释放目标条目空间，失败则回滚目标条目和当前草稿。
- 暂存只在当前浏览器保存 → 不承诺跨设备同步；存储不可用时明确提示并保留页面内编辑。
- 旧版本回退会暂时隐藏暂存 → 不删除数据，重新升级后恢复。
- 大列表或长文本可能占用本机配额 → 20 条、20k 单条、100k 合计的上限在模型和存储两层校验。

## Migration Plan

- 纯前端新增键，不迁移旧 v1 当前草稿；旧应用回退不会删除 `webmux.scratch.`。
- 部署时重新构建 `web/dist` 再编译嵌入式二进制。
- 回滚为上一前端构建即可；页面内未保存的暂存会随刷新丢失，已保存记录保留到旧版本再次读取或过期清理。
