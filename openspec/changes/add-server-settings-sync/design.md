## Context

WebMux 是单用户、单实例的 Go 服务，浏览器通过已认证的 `/api` 与 `/ws` 访问同一台机器。当前的配置边界如下。

| 位置                  | 内容                                                                                                                                                                                    | 生命周期                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `config.toml`         | `listen`、`token`、`state_dir`、`allowed_origins`、`tunnel.*`、`default_cwd`、`scrollback_bytes`、`idle_after_seconds`、`prompt_patterns`、`agent_protocol`、`bell_attention`、`push.*` | 启动时读取，修改后重启生效                                                              |
| `<state_dir>`         | 仓库清单、启动配置、Web Push 订阅、独立的隧道覆盖配置 `tunnel-settings.json`                                                                                                            | 服务端持久化；隧道配置已有专用网页入口，凭据只写不回填                                  |
| 浏览器 `localStorage` | `theme`、`fontSize`、`preview`、`codeLineNumbers`、`codeDiffOverflow`、`quickCommands`、`homeWorktrees`                                                                                 | 仅当前浏览器；主题、快捷指令与主页工作树通过 `storage` 事件同步标签页，其余偏好无此监听 |
| 浏览器组件状态        | `forceSoftKeys`（强制底部工具栏）                                                                                                                                                       | 刷新即丢失                                                                              |
| 浏览器其他数据        | `token`、`push.subscriptionId`、`recentDirs`、`lastLaunch`、`customCommand`、`clientId`、草稿与暂存正文                                                                                 | 设备或会话本地                                                                          |

`tunnel.*` 是部署默认值而非仅能通过 TOML 管理的运行时设置：现有公网访问页与托盘已把开关、模式、凭据和主机名保存到 `tunnel-settings.json` 并即时应用，文件存在时覆盖对应 TOML 默认值；`cloudflared` 与 `download_mirrors` 仍只由 TOML 管理。本变更保留该专用服务和优先级，不把隧道凭据搬入通用偏好快照。

`internal/launch` 已经提供了可复用的服务端状态模式：独立文件锁、0600 文件、`statefile` 原子替换、损坏时保留原文件并让接口返回 503、不可用时不阻塞其他功能。本变更沿用该模式，不为设置单独发明一套持久化。

## Goals / Non-Goals

### Goals

- 同一实例上的所有已认证浏览器与设备读取同一份用户偏好。
- 主题、字号等即时生效的设置在任意客户端修改后，其他已打开的客户端无需刷新即可看到。
- 明确破坏性升级：旧浏览器偏好不上传，用户通过新设置入口重新配置。
- 设置存储损坏、被另一实例占用或暂时不可达时，终端、会话与其他功能继续工作。
- 明确区分“跨设备同步的偏好”“必须留在设备的凭据与数据”“继续由 TOML 管理的启动与安全配置”。

### Non-Goals

- 多用户账户、按用户隔离设置、权限角色或共享给未认证访客。
- 从网页修改 `config.toml`、重启服务或增加 `listen`、`token`、`state_dir`、`allowed_origins`、`push.*` 等启动与安全项的通用编辑入口；既有公网访问专用配置不变，不纳入 `settings.json`。
- 同步 `token`、Web Push 订阅、草稿与暂存正文、最近目录、上次启动选择、临时命令或 `clientId`。
- 跨 WebMux 实例同步、云端账户、设置端到端加密或设置版本历史。
- 多人同时编辑同一份设置的合并算法；只提供修订号冲突检测、客户端重放与一次自动重试。
- 把 `scrollback_bytes`、`idle_after_seconds`、`prompt_patterns` 等进程策略改成运行时可编辑；这些项涉及会话重建或全局行为，留待独立变更。

## Decisions

### 1. 配置分层与同步范围

按“是否需要跨设备一致”和“是否包含凭据或设备身份”划分。

| 键                             | 当前                                         | 目标                                           | 理由                                 |
| ------------------------------ | -------------------------------------------- | ---------------------------------------------- | ------------------------------------ |
| `theme`                        | `localStorage`，未设置为跟随系统             | 服务端，`null` 表示跟随系统                    | 纯展示偏好，跨设备一致符合预期       |
| `fontSize`                     | `localStorage`，默认按粗指针 13 / 细指针 14  | 服务端，`null` 表示设备默认                    | 用户主动调整后应跨设备保留           |
| `preview`                      | `localStorage`，默认 `{lines: 10, skip: 1}`  | 服务端，`null` 表示默认                        | 纯展示偏好                           |
| `codeReader.lineNumbers`       | `localStorage`，默认 `show`                  | 服务端，`null` 表示 `show`                     | 纯展示偏好                           |
| `codeReader.diffOverflow`      | `localStorage`，默认 `scroll`                | 服务端，`null` 表示 `scroll`                   | 纯展示偏好                           |
| `quickCommands`                | `localStorage`，未保存显示 `/resume`、`/new` | 服务端，`null` 表示未初始化，`[]` 表示明确为空 | 用户内容，最需要跨设备共享           |
| `homeWorktrees`                | `localStorage`，按仓库保存固定工作树 ID      | 服务端，`null` 表示未整理                      | 跨设备主页布局一致                   |
| `forceSoftKeys`                | 组件状态，刷新丢失                           | 服务端，`null` 表示关闭                        | 已存在的用户可见开关，一并持久化     |
| `lastLaunch`、`customCommand`  | `localStorage`                               | 保持本地                                       | 是“上次操作”，不同设备各自选择更合理 |
| `recentDirs`                   | `localStorage`                               | 保持本地                                       | 是使用历史，不是配置                 |
| `token`                        | `localStorage`                               | 保持本地                                       | 凭据，不能通过设置接口离开设备       |
| `push.subscriptionId`          | `localStorage`                               | 保持本地                                       | 每个浏览器/设备有各自的推送端点      |
| 草稿、暂存、`draftPersistence` | `localStorage`                               | 保持本地                                       | 正文大、含隐私、语义就是“在本机保存” |
| `clientId`、`clientLive`       | `sessionStorage`                             | 保持本地                                       | 会话运行期身份，不是配置             |
| TOML 启动与安全项              | `config.toml`                                | 保持 TOML                                      | 启动引导、安全边界、凭据或全局策略   |

快捷指令的数据与菜单语义由 `terminal-quick-commands` 继续定义；主页工作树的选择语义由本能力定义；本能力同时负责两者的存储、同步与故障边界。

### 2. 设置文档与 `null` 语义

`settings.json` 使用版本化对象，只保存显式设置过的键；缺失键与 `null` 同义，表示“未设置”。

```json
{
  "v": 1,
  "revision": 7,
  "updatedAt": "2026-10-25T12:00:00Z",
  "values": {
    "theme": "dark",
    "fontSize": 15,
    "preview": { "lines": 12, "skip": 2 },
    "codeReader": { "lineNumbers": "hide", "diffOverflow": "wrap" },
    "quickCommands": [
      {
        "id": "3f2a9c0d1e4b5a6c",
        "name": "",
        "command": "/resume",
        "enter": true
      }
    ],
    "homeWorktrees": { "repo-id": ["worktree-id"] },
    "forceSoftKeys": false
  }
}
```

API 快照始终返回全部已知键，未设置的键为 `null`，避免客户端区分“缺失”和“默认”：

```json
{
  "revision": 7,
  "updatedAt": "2026-10-25T12:00:00Z",
  "values": {
    "theme": "dark",
    "fontSize": 15,
    "preview": { "lines": 12, "skip": 2 },
    "codeReader": { "lineNumbers": "hide", "diffOverflow": "wrap" },
    "quickCommands": null,
    "homeWorktrees": null,
    "forceSoftKeys": null
  }
}
```

`null` 在 PATCH 中表示“恢复默认”，在 GET 中表示“当前使用默认”。`quickCommands` 的 `null` 与 `[]` 必须保持不同，否则无法区分“从未初始化”与“用户删光后不要再补回预置指令”。

### 3. 持久化与不可用状态

- 路径：`<state_dir>/settings.json`；锁：`<state_dir>/settings.json.lock`。两个文件均为 0600，目录按现有规则创建并确保 0700。
- 启动时打开锁文件并取得独占非阻塞锁，随后才读取设置文件。锁冲突时本实例的设置服务不可用，不读取或写入设置文件；其他服务照常启动。
- 设置文件不存在时视为全部为 `null`、`revision` 为 0，且不创建文件；第一次成功 PATCH 才写入并原子替换。
- 保存使用 `internal/statefile` 的 descriptor/typed handle：同目录临时文件、0600、`fsync`、关闭、`rename`、目录同步；失败时保留最后已确认内存快照并返回 503，冻结后续写入；commit_uncertain 不宣称磁盘回滚。
- 文件无法解析、版本不支持、字段非法或超过大小上限时，保留原文件，不自动重建、不覆盖、不改名，设置接口返回 503；修复或删除文件后需要重启才能重新加载。
- 设置文件的锁与 `launch-configs.lock`、`push` 存储彼此独立：设置不可用不影响启动配置，反之亦然。
- 读取时先 `Stat` 限制文件大小，再解析；避免损坏文件导致无界内存占用。

### 4. 修订号与部分更新

- `revision` 是从 0 开始的单调递增整数；每次成功 PATCH 加 1，失败、校验不通过或 409 不改变修订号。
- `PATCH /api/settings` 请求体：

```json
{
  "baseRevision": 7,
  "changes": {
    "theme": "light",
    "preview": null
  }
}
```

- `baseRevision` 必须等于当前修订号，否则返回 409 且不修改任何内容；客户端重新 GET 后重放用户操作。
- `changes` 必须是非空对象，键只能是已知设置名；未知键返回 400。值为 `null` 表示恢复默认。
- 一个 PATCH 的所有字段整体校验、整体写入：任意字段非法则整个请求 400，不产生部分更新。
- 成功返回 200 与完整快照，客户端无需再 GET。
- 单用户多设备仍可能出现冲突；409 响应只包含 `{"error": "设置已被其他客户端修改"}`，不包含设置值。客户端按操作语义重放：
  - 标量设置直接以最新快照的 `revision` 重试目标值；
  - `preview` 与 `codeReader` 记录用户本次改动的子字段及目标值，重读后在最新对象上只覆盖这些子字段，再提交完整的顶层对象；最新值为 `null` 时先展开该组默认值。未改动的兄弟字段保留远端值；同一子字段冲突时本次重试的目标值生效，一次操作明确修改两个子字段时两者都重放；
  - 分组“恢复默认”是显式的整组重置，409 后仍重放该顶层键的 `null`，不与远端子字段合并；
  - 快捷指令按条目 ID 重放新增、修改、删除或移动；目标条目已不存在时提示并刷新；
  - 主页工作树按添加或移除的工作树 ID 重放；只写用户本次操作，不因读取快照自动清理。
- 自动重试一次；仍冲突或字段已被删除时保留用户输入并显示可重试的错误。
- 请求体上限为 2 MiB。现有 `/api` 的 64 KiB `decode` 上限不足以容纳 50 条、每条最长 4096 字符的快捷指令，设置路由使用专用的限长解码器；响应不设额外上限，但受快照数据模型约束。

### 5. 跨客户端同步通道

- 新增 `GET /ws/settings`，与 `/ws/sessions`、`/ws/s/{id}` 一样经过 `/ws/*` 的认证、Host 与 Origin 校验，并使用现有 `webmux` 子协议。
- 捕获完整快照与注册订阅在同一设置锁内原子完成，并与 PATCH 的提交、修订号递增和事件入队共用该锁。锁内先把修订号 N 的快照放入新订阅的队首，再注册该订阅；后续提交只能排在快照之后，按修订号顺序入队。网络写入在解锁后进行，不能持锁等待客户端。这样并发 PATCH 要么已包含在快照中，要么作为后续更新送达，不存在订阅空窗。
- 连接建立后第一条帧为完整快照：

```json
{
  "type": "settings",
  "settings": {
    "revision": 7,
    "updatedAt": "2026-10-25T12:00:00Z",
    "values": {
      "theme": "dark",
      "fontSize": 15,
      "preview": null,
      "codeReader": null,
      "quickCommands": null,
      "homeWorktrees": null,
      "forceSoftKeys": null
    }
  }
}
```

- 每次成功 PATCH 后广播更新帧，只包含本次变化的顶层键：

```json
{
  "type": "settings.update",
  "revision": 8,
  "updatedAt": "2026-10-25T12:01:00Z",
  "changes": { "theme": "light" }
}
```

- 客户端按 `revision` 合并：`revision` 等于本地值加 1 时应用 `changes`；大于本地值加 1 或收到未知键时重新 GET 快照。旧修订号的重复帧直接忽略。
- 每个连接只有一个写协程。订阅队列有界；客户端读取过慢时以 1013 关闭连接，客户端重连后重新取完整快照，服务端不阻塞 PATCH 或其他客户端。不尝试把多个变化帧合并成部分更新，避免客户端漏掉中间键。
- 客户端断线后指数退避重连；`online`、`visibilitychange` 恢复时也触发一次快照校验，避免长时间后台造成旧状态。
- 设置帧与终端帧、会话列表帧使用不同的 WebSocket 路径，互不阻塞；设置同步失败不影响终端连接。

### 6. 首屏缓存与启动顺序

主题和字号需要在下一次解析前生效，不能等待认证后的网络请求。浏览器保留一份上次成功同步的只读缓存：

- 键：`webmux.settingsCache`，内容为 `{revision, updatedAt, values}`。
- 启动时同步读取缓存，先应用 `theme`（`null` 时跟随系统）与 `fontSize`（`null` 时按设备默认），避免主题闪烁与字号跳变。
- 认证成功后打开 `/ws/settings`，用服务端快照覆盖本地状态并更新缓存；服务端值与缓存不同时以服务端为准。
- 缓存只用于读取和首屏渲染，不接收用户写入；所有修改仍走 PATCH。
- 缓存损坏、版本不符或缺字段时忽略并删除；缓存写入失败（配额或隐私模式）不影响使用，只是下次启动没有首屏值。
- 缓存可能包含快捷指令正文，因此只保存在与服务端同源的 `localStorage`，不发送给第三方；退出登录不清除缓存，但认证失效后页面不展示其中的快捷指令，直到重新认证成功。

### 7. 破坏性升级与旧浏览器键

用户确认不需要兼容性。本次不读取、不上传、不删除旧偏好键，不创建迁移标记。服务端快照是唯一权威来源；`webmux.settingsCache` 只保存成功读取或提交后的快照，不接收未确认用户写入。缺失服务端字段为 `null`，使用设备默认；旧本地值不能覆盖它。

### 8. 各设置的默认值与校验

| 设置            | 校验                                                                                                             | 默认（`null`）                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `theme`         | `light` \| `dark`                                                                                                | 跟随系统                                        |
| `fontSize`      | 整数 8–20                                                                                                        | 粗指针 13，细指针 14                            |
| `preview`       | `lines` 1–50，`skip` 0–50，均为整数                                                                              | `{lines: 10, skip: 1}`                          |
| `codeReader`    | `lineNumbers` 为 `show` \| `hide`，`diffOverflow` 为 `scroll` \| `wrap`                                          | `{lineNumbers: "show", diffOverflow: "scroll"}` |
| `quickCommands` | 0–50 条；`id` 1–64 字符且唯一；`name` 去空白后 ≤40 字符；`command` 去空白后非空且 ≤4096 字符；`enter` 为布尔     | `null` 显示 `/resume`、`/new`                   |
| `homeWorktrees` | 最多 200 个仓库；仓库 ID 1–128 字符；每个仓库最多 1000 个工作树 ID，每个 ID 1–128 字符；全部条目合计最多 2000 个 | `null`，每个仓库默认只显示主工作树              |
| `forceSoftKeys` | 布尔                                                                                                             | `false`                                         |

快捷指令保存时继续把 CRLF/CR 统一为 LF 并移除末尾换行；服务端做同样的规范化，避免不同客户端写入不一致的文本。所有字符串必须是有效 UTF-8；设置接口不新增控制字符规则，快捷指令正文沿用现有终端输入与发送规则。

### 9. 服务端不可用时的降级

- 设置接口 503 或网络断开时，页面使用第 6 节的缓存只读展示；没有缓存时使用默认值。认证失败仍进入现有登录流程，登录页可以用缓存主题与字号渲染，但不展示缓存中的快捷指令。
- 设置页显示“设置暂不可用”的原因与服务端返回的状态文件路径，禁用写入，提供“重新读取”；其他卡片和终端操作保持可用。
- 快捷指令菜单使用缓存中的最后一份列表，只读；没有缓存时显示预置指令并说明暂不可保存。终端的直接发送、草稿与快捷指令菜单本身不依赖设置服务。
- 服务恢复后重新 GET 并覆盖缓存；不自动重放离线期间的修改，因为本地不保存待写队列，避免把过期意图覆盖到其他设备的新值。
- 设置文件损坏时，错误信息包含 `settings.json` 路径但不包含任何设置值；修复或删除文件后需重启服务。

### 10. 设置页与各入口

- 设置页说明：除 token、推送订阅、草稿、最近目录和上次选择等设备本地数据外，偏好保存在服务端并在所有设备间同步；TOML 启动与安全配置仍需编辑文件并重启，既有隧道专用配置仍可即时保存应用，不与通用偏好合并。
- 新增“外观与阅读”卡片：主题（跟随系统/浅色/深色）、字体大小（8–20，含当前值）、输出预览行数与跳过行数、代码行号、Diff 换行、强制底部工具栏。快捷指令卡片继续保留新建、编辑、排序、删除与上限逻辑，说明改为服务端保存。
- “恢复默认”对单个分组使用 PATCH `null`；快捷指令的删除全部仍需确认，并保存为 `[]`，不重新补回预置指令。
- 终端顶栏的主题切换、字体大小菜单、代码阅读器的行号与换行开关、主页的添加/移除工作树，全部写入同一设置存储并立即更新本地状态；服务端返回成功后再更新缓存。
- 修改采用乐观更新：先应用本地状态，PATCH 失败时回滚并显示错误；409 按第 4 节重放一次。这样主题和字号不需要等待网络即可响应。
- 同步状态只在设置页以简短文字显示“已同步”或不可用原因，不在终端持续显示，避免打扰。
- 设置页的深链接锚点继续保留：`#quick-commands`、`#launch-configs`、`#drafts`；新增 `#appearance`。当前 `#drafts` 仍只管理本机草稿。

### 11. 安全与隐私

- 设置接口和 WebSocket 继承 `/api/*`、`/ws/*` 的认证、Host 与 Origin 校验：浏览器 HTTP 请求使用 `Authorization: Bearer <token>`；WebSocket 握手提供 `webmux` 与 `webmux.token.<base64url(token)>` 子协议，服务端只选择 `webmux`，不回显 token 子协议。保留现有中间件对 `webmux_token` Cookie 的兼容回退，但浏览器不依赖 Cookie，也不把 token 放进 URL。本机 Unix 套接字继续按对端 UID 校验。不新增 CORS 例外、匿名端点或静态文件。
- `settings.json` 与 `settings.json.lock` 为 0600，状态目录 0700；不回显 Token，不把 Token、Web Push 订阅或草稿写入设置文件。
- 快捷指令正文可能包含提示词或密钥；服务端不记录请求体、设置值或迁移日志。错误只包含字段名、限制与文件路径，不回显值。
- 请求体 2 MiB、文件 4 MiB、条目数量与字符串长度共同限制存储放大与拒绝服务；服务端读取时仍完整校验，不信任客户端。
- 本变更不声称对设置文件做应用层加密；拥有服务账户文件读取权限的用户仍可读取快捷指令正文，与现有启动配置环境变量的威胁模型一致。

### 12. 备选方案

- 全部搬进 `config.toml`：需要手写 TOML 并重启，无法作为客户端设置入口，也无法由非管理员设备修改；不采用。
- 只保留 `localStorage`，增加 `BroadcastChannel`/`storage` 同步：只能同一浏览器，不能跨设备；不采用。
- 每次变化广播完整快照：快捷指令可达约 200 KiB，主题切换也要传全部内容；改为变化键事件，连接时仍发完整快照。
- 每个设置一个 REST 端点：路由、错误码与冲突语义成倍增加；统一 PATCH 更适合单用户少量设置。
- 不做修订号，后写覆盖：多设备同时编辑快捷指令会静默丢失操作；采用乐观并发与操作重放。
- 把 token、推送订阅也同步：会把凭据复制到其他设备，推送端点也不能共用；不采用。
- 把草稿搬到服务端：正文大、包含隐私，且现有语义是“本机保存”；留待独立能力。
- 使用 SQLite：单用户、小文档、已有原子 JSON 模式足够；不引入数据库依赖。
- 把 `scrollback_bytes`、`idle_after_seconds` 等也搬入：需要会话重建或全局策略变更，超出“客户端偏好同步”；另开变更。

## Risks / Trade-offs

- [跨设备同步字号可能不适合所有屏幕] → `null` 保留设备默认，只有用户主动调整后才同步；不提供按设备覆盖，避免模型复杂化。
- [`localStorage` 缓存仍包含一份快捷指令正文] → 仅同源可读、只作首屏与降级读取、不接收用户写入；不改变现有单用户威胁模型。
- [409 重放可能覆盖其他设备刚修改的同一键] → 按操作语义而非整份列表重放，冲突时刷新并提示；自动重试最多一次。
- [设置文件损坏后需要重启恢复] → 与启动配置现有行为一致，优先保留用户数据；设置页给出路径与原因。
- [WebSocket 增加一个长连接与广播路径] → 复用认证、Origin、子协议与单写协程；有界队列与冲突重取避免慢客户端拖垮服务。
- [旧测试与规格断言“仅保存在当前浏览器”] → 同一变更更新 `terminal-quick-commands` 与相关 Vitest/Playwright 断言，避免两套语义并存。
- [新增状态文件使文档与部署说明过时] → tasks 中列明 README、架构、部署与协议文档的同步更新。

## Migration Plan

先停止旧服务，备份状态目录并核实外部入口，然后升级。文件名、锁名和格式允许破坏性变化，不做双读、双写或浏览器偏好自动迁移。新旧版本不能共用同一状态目录并发运行。正常缺失的 `settings.json` 使用 revision 0 和全 null 快照，首次显式保存才创建数据文件。需要回退时停止新版并从独立备份恢复，不承诺混合版本运行。

## Open Questions

- 是否为不同设备保留字号或主题的按设备覆盖？当前选择不保留，按 #119 的“跨客户端同步”目标统一。
- 是否在后续变更中把 `default_cwd`、`scrollback_bytes`、`idle_after_seconds` 等运行策略也搬入设置存储？本变更明确不做，避免把需要会话重建或全局生效的项混入客户端偏好。
- 是否同步 `recentDirs`？当前不纳入：它是使用历史而非配置，且不同设备的本机路径可能不同。
