## Context

动机见 proposal.md。本次仅规划，保留 #130 的浏览器图形实现和 omp 首次预置兼容变量，不在本变更中实施以下切换。

已核对的实现边界：

- `internal/session/session.go` 在创建 PTY 前由 `env.go` 组装环境，当前默认 `TERM=xterm-256color`、`COLORTERM=truecolor`，过滤宿主终端身份；进程不等待浏览器附着。
- `web/src/hooks/terminal-socket.svelte.ts` 通过浏览器图形层生成应答，历史回放期间抑制回复；hub/session 按既有控制权决定哪个连接可回写设备应答。
- `web/src/kitty-graphics.ts` 识别图形协议并串行交给图形与 xterm 解析器，当前已有图形查询先于随后文本解析的顺序保证；它不能代替没有浏览器时的应答方。
- #130 的隔离实测确认 omp 18.12.6 在强制变量下发出 PNG 传输和放置；没有证明未设置变量时的通用自动发现，也没有覆盖浏览器未就绪时的一次性探测。
- Kitty 规范要求图形查询在后续 DA1 前应答，参见 https://sw.kovidgoyal.net/kitty/graphics-protocol/#querying-support-and-available-transmission-mediums 。

现有 `terminal-control` 把所有自动应答交给负责客户端；本规划必须同步修改该要求，不能只在后端偷偷多写一份应答。`session-launch-environment` 的显式变量优先规则保持；其余旧预设相关规格差异不是本次修订范围。

## Goals / Non-Goals

**Goals:**

- 在程序创建前给出真实身份；基础图形查询和 DA1 在无浏览器、晚附着和断线时仍有唯一、顺序确定的应答方。
- 能力是 WebMux 虚拟会话的固定子集，不从当前宿主终端或某一次浏览器连接推断，切换控制端不改变程序已经探测到的基础契约。
- 保持 PTY 原始输出、offset、回放及观察端语义；不把设备回复当成键入，也不阻塞输出读取。

**Non-Goals:**

- 本次合并不实现此设计，不删除或推广 omp 强制变量。
- 不伪装完整 Kitty，不实现文件/共享内存、Unicode 占位符、动画、相对放置或 Kitty 键盘协议。
- 不构建后端终端模拟器、持久图片缓存、完整屏幕恢复或跨服务重启的会话存储。
- 不强迫现有配置迁移，也不保证不进行探测的未知应用和所有原生终端能显示图片。

## Decisions

### 1. 使用会话固定的虚拟能力，而非当前浏览器能力

基础能力定义为 WebMux 已支持的直接图片传输子集；运行中不能因浏览器断线变成“不支持”，接管也不增加新协议。原生 attach 是该虚拟会话的一种显示客户端，不等于本地父终端获得了同样能力；其文字透传与输入控制保持可用，图片显示需本地终端自身支持。

备选的“浏览器先握手再启动程序”会改变 CLI 无浏览器启动和持久会话语义；“没有浏览器就不支持”会让应用在第一次探测后永久降级。均不采用。

### 2. 启动身份只说明自己，不代替协议探测

在现有会话环境组装中设置 `TERM_PROGRAM=webmux` 和服务版本，保持 xterm 兼容 TERM，显式变量仍优先。环境声明必须在 `exec` 前完成，不给已运行进程发送所谓启动广播。应用不认识该身份时可以进行标准查询或使用应用专用配置；不能假设增加这个变量就修复所有应用。

不设置伪造 Kitty 窗口 ID 或默认 `TERM=xterm-kitty`，避免触发未实现的功能和本地传输猜测。

### 3. session 拥有最小查询应答，浏览器继续拥有绘制

会话服务在实时 PTY 输出路径旁识别有界的 Kitty `a=q` 和 DA1 查询，不改变发布和环形缓冲中的原始字节，不解码/绘制图片，不维护光标和屏幕。基础应答从会话内单一 FIFO 进入现有可取消 PTY 写入路径；同一序列不能与用户写入交错，不能持状态锁等待 PTY 可写。

DA1 必须一起切换到会话权威，避免浏览器先回答 DA1 而后台图形查询仍未完成。DA1 的能力位须基于已实现的 xterm 兼容基线固定，不额外宣称未实现的特性。依赖当前屏幕和尺寸的其他查询仍交给负责客户端，不在此处扩大解析范围。

查询暂存采用固定 64 KiB 上限；只对已终止、语法及格式有效且在已支持范围内的查询返回成功。查询验证不能解压或分配图片像素，不支持和超限请求失败关闭。内部应答队列必须有界；超限不能堵塞 PTY 读取或通过随后回放重试，退出取消必须停止写入。普通大图片传输继续按现有图形层预算处理，不被该查询上限误伤。

优先把纯协议识别放在服务拥有的最小内部文件中；只有确实需要前后层共享 Go 类型时才抽取 stdlib-only 共享包，并按架构规则分类。服务不得编码客户端 JSON，controllers 不得直接做进程操作，配置和构造注入仍留在 `cmd/`。

### 4. 单一权威需要同时切换所有客户端

会话通过有类型的状态显式告知客户端哪些查询已经由会话接管。hub/wire/contract、浏览器 schemas/消费者、原生 attach 一起迁移，不长期并存两种权威，不增加旧行为兼容别名。客户端版本不兼容时明确失败，不静默产生第二份应答。

浏览器对已接管的 Kitty 查询不发送回复，并截获已接管的 DA1，防止 xterm 再答；图片绘制仍在原图形层。原生 attach 在显示输出侧消除这些已接管查询对本地终端的触发，而不是在用户输入中按字节猜测和删除响应；流 offset 仍按未过滤的原始字节推进。其他查询透传和控制端规则不变。

### 5. 实时查询与回放严格分开

服务只在初次读取实时 PTY 字节时处理查询，历史缓存不作为应答输入源；浏览器和 CLI 的回放也不重答。完整重新同步清理图片状态但不重新运行协议发现。普通增量输出和断线期间的新查询仍实时应答，取消使用会话运行代际隔离，不能写入后续会话。

## Risks / Trade-offs

- [需要在后端识别少量终端序列] → 仅限固定能力查询和 DA1，不引入完整模拟器；跨分块、恶意输入与恢复边界做确定性验证。
- [能力协商和图像渲染范围漂移] → 同一份有效/非法查询样例用于服务应答和浏览器解析的行为验证，资源限制与不支持介质必须一致，不以复制实现的测试代替协议断言。
- [原生终端也会自动回复] → 输出侧抑制已接管查询，保留原始 offset；不根据用户输入的字节形状推断来源。
- [浏览器图形超限或历史已截断] → 能力支持不等于每张图片必然保留；继续执行资源预算并保留现有截断说明，不承诺未实现的图片持久恢复。
- [环境识别依赖应用名单] → 正确实现标准查询但保留应用专用配置，不能通过伪造 Kitty 身份扩大能力声明。

## Migration Plan

1. 在隔离后端和真实 PTY 中建立启动探测证据：无客户端立即查询、延后附着、查询后输入、查询与 DA1 跨块；明确区分当前行为与未来验收结果。
2. 实施会话基础能力与应答顺序，同时迁移 wire、浏览器及 CLI 的所有查询所有者；全切换前不得启用服务端自动应答。
3. 核对只读观察、控制接管、断线、新旧代际、取消、输入不被误删和未修改的原始流 offset，再用真实 omp 与 kitten 验证兼容范围。
4. 更新受影响的 US-D12、US-D06、US-B08 及准确的协议/使用说明；不把应用专用设置描述成通用自动发现。
5. 回滚时整体回退服务端应答与全部客户端所有权切换，回到 #130 的浏览器应答和显式配置；不重写已有启动配置文件。
