## Context

当前实现与启动命令相关的路径：

- `internal/config/config.go` 在启动时加载 `[[presets]]`，默认生成 `shell`、`claude`、`codex`、`omp` 四条预设；`Validate` 会把 `shell` 预设解析为实际的 `shell -l -i`。修改预设后需要重启服务。默认预设本身也会随版本修正（例如 #90 把 `omp` 改为经 `bash -ic` 启动以加载 bashrc）。
- `web/src/components/NewSessionSheet.svelte` 从 `GET /api/presets` 读取预设，并额外支持“追加参数”和自定义命令；上次预设与自定义命令分别保存在浏览器 `localStorage` 的 `webmux.lastPreset`、`webmux.customCommand`。追加参数由 `web/src/api.ts` 的 `parseArgs` 按 argv 规则切分，不经过 shell。
- `POST /api/sessions`（`internal/api/router.go`）已接受 `cwd`、`preset`、`cmd`、`args`、`name`、`workspace`、`env`。`env` 由 `session.ValidateEnv`（`internal/session/env.go`）校验名称、NUL 与保留变量 `WEBMUX_SESSION_ID`；前端从未发送该字段。
- `workspace.Service.CreateSession` 已经接受完整 argv 与 `env`，并负责目录、工作树、并发启动与仓库关联校验；`session.Manager.Create` 不需要为启动配置做任何改动。
- 服务端状态目录来自 `state_dir`，默认 `~/.local/state/webmux`（`XDG_STATE_HOME` 优先）。`internal/push/store.go` 与 `internal/workspace/registry.go` 已确立原子写入方式：同目录临时文件、`chmod 0600`、写入、`fsync`、关闭、`rename`、目录同步。
- `workspace.New` 用 `syscall.Flock` 对 `<state_dir>/repositories.lock` 加独占非阻塞锁；拿不到锁时服务照常启动，只把仓库清单标为不可用。因此“同一 `state_dir` 只允许一个实例”在启动时并未强制，第二个实例仍会运行，`push.json` 也没有跨进程锁。
- 设置页 `web/src/pages/Settings.svelte` 顶部说明为“快捷指令、草稿和预览只保存在当前浏览器。公网访问与通知推送涉及服务端能力……”，并按卡片分组；`NewSessionSheet` 在桌面用 Dialog、移动端用 Drawer，二者共用同一表单片段。
- `/api/*` 已有统一认证、Host 与 Origin 校验；请求体使用 `decode`，拒绝未知字段、只接受一个 JSON 对象并限制为 64 KiB。启动配置可以执行任意命令，这与现有自定义命令接口的权限边界相同，不新增授权模型。

本变更的规划工件与实现在 PR #103 中一并交付。

## Goals / Non-Goals

**Goals:**

- 用服务端持久化的“名称 + 完整 argv + 环境变量”替代浏览器本地的自定义启动方式，使用户配置跨重启、跨浏览器与设备可用。
- TOML 预设保持为实时的内置预设，与用户启动配置并列；预设的新增与修正无需迁移即可到达用户。
- 保存时把预设与追加参数固化为完整 argv；TOML 预设后续变化不影响已保存配置。
- 复用现有 `POST /api/sessions`、`session.ValidateEnv`、`workspace.CreateSession` 与终端生命周期，不建立第二套 PTY 启动路径。
- 沿用状态目录的原子写入、0600 文件权限、进程内互斥与失败回滚约定，并用独立文件锁防止两个实例互相覆盖。
- 环境变量值只在需要编辑时下发，列表与新建会话页不接收值。
- 存储损坏、不可用或被占用时只禁用启动配置功能，不影响内置预设、会话与终端。
- 设置页与新建会话页在桌面、移动端与明暗主题下都可完成配置管理和启动。

**Non-Goals:**

- 首页一键启动、配置级默认工作目录、工作树绑定。
- 在 `SessionInfo` 中增加配置 ID 或配置名称。
- 配置导入/导出、变量或占位符模板、按 agent 或目录过滤、排序、标签、共享链接。
- 将配置写回 `config.toml`，把 TOML 预设复制进启动配置文件，或让已保存配置跟随 TOML 预设变化。
- 在设置页编辑、隐藏或覆盖 TOML 内置预设。
- 多用户权限、配置级访问控制或加密存储；沿用单用户与已认证 API 的安全模型。
- 为 `repositories.json` 或 `push.json` 补加锁；本变更只保护自己的文件。

## Decisions

### 0. 已确认的产品取舍

| 问题 | 结论 |
|---|---|
| TOML 预设与启动配置的关系 | 预设作为只读“内置预设”实时展示，不种子、不复制；用户可从预设填入后另存为启动配置 |
| 从预设填入时的默认名称 | 预设的 `label`（如“Claude Code”），用户可修改 |
| 列表是否返回环境变量值 | 否；列表只返回变量名，值通过 `GET /api/launch-configs/{id}` 读取 |
| 配置是否包含默认工作目录 | 否；每次启动仍选择目录，配置级 `cwd` 留到下一期 |
| 是否保留“临时命令（不保存）” | 是，折叠为高级入口，只承载一次性的自定义命令 |
| 持久化格式 | 状态目录 JSON；不写回 `config.toml` |
| 环境变量值是否默认遮挡 | 是，提供显示切换 |
| 首页一键启动 | 下一期，直接复用 `POST /api/sessions {configId}` |

以上取舍已由维护者在 PR #103 评审中确认；若之后改变，先更新本工件再实现。

### 1. 数据模型与文件格式

`<state_dir>/launch-configs.json`：

```json
{
  "v": 1,
  "configs": [
    {
      "id": "k3m9q2x7",
      "name": "Claude 恢复会话",
      "cmd": ["claude", "--resume"],
      "env": { "ANTHROPIC_BASE_URL": "https://example.test" },
      "createdAt": "2026-10-23T12:00:00Z",
      "updatedAt": "2026-10-23T12:00:00Z"
    }
  ]
}
```

- `id` 由服务端生成，8 位小写 base32（字符集 `a-z2-7`），与现有会话 ID 的格式一致；生成后与现有配置比较，冲突时重新生成。客户端不能指定或修改。
- `name` 去除首尾空白后按 Unicode 字符计 1–64 个字符，并在启动配置之间唯一（去空白后精确比较，区分大小写）。重名返回 409。启动配置与内置预设分组展示，因此不要求与预设的 `name` 或 `label` 区分。
- `cmd` 是保存时解析出的完整 argv，包含追加参数；长度 1–128 项，第一项非空，单项 UTF-8 不超过 8 KiB。除第一项外允许空字符串参数，以保留 `parseArgs` 的空参数语义。
- `env` 是字符串到字符串的映射，最多 64 项；名称与值必须满足 `session.ValidateEnv`（名称 `^[A-Za-z_][A-Za-z0-9_]*$`、值不含 NUL、`WEBMUX_SESSION_ID` 保留），值不超过 8 KiB。空映射序列化为 `{}`，不能为 `null`。
- 时间在 JSON 中使用 UTC RFC 3339；`createdAt` 创建后不变，`updatedAt` 每次成功更新刷新。
- 配置最多 100 条。`POST`/`PUT` 请求体沿用现有 64 KiB 上限，因此各项上限之外还受整体请求大小约束。
- `configs` 按创建顺序（最旧在前）返回；更新不改变顺序。空列表序列化为 `[]`。

完整 argv 是命令快照，不保存来源预设名与参数列表。这样 TOML 预设被修改或删除后，已保存配置仍按原命令启动；代价是界面必须明确提示“保存的是创建时的命令副本”。需要跟随预设修正的用户应直接使用内置预设。

### 2. 存储服务、文件锁与故障处理

新增 `internal/launch` 包：

- `types.go`：配置结构、输入校验、规范化、ID 生成；`cmd` 与 `env` 在保存和启动时都做防御性复制，避免共享切片或映射被调用方修改。
- `store.go`：`Service` 持有进程内互斥锁、文件锁句柄、文件路径、配置切片与不可用原因。`Close` 释放文件锁。
- 启动接线：`cmd/webmux/main.go` 在 `workspace.New` 之后、`api.New` 之前创建服务，退出时 `Close`；构造失败不阻止服务启动，只让服务进入不可用状态。
- 加载流程：确保状态目录存在且为 0700 → 打开 `<state_dir>/launch-configs.lock`（0600）并以 `syscall.Flock(LOCK_EX|LOCK_NB)` 加锁，进程生命周期内持有 → 读取 `launch-configs.json` → 文件不存在时视为空列表，不写文件 → 解析或校验失败时记录不可用原因，不修改文件。
- 文件锁：拿不到锁说明同一 `state_dir` 有另一实例在运行；本实例的启动配置进入不可用状态，原因为“状态目录已被另一实例使用”，不读写 JSON 文件。这样即使 `workspace` 与 `push` 在锁冲突时继续运行，也不会出现两个进程以后写覆盖用户配置。锁文件与 `repositories.lock` 分开，避免依赖其他服务的加锁时机。
- 保存流程与 `internal/push/store.go` 一致：同目录临时文件、`chmod 0600`、写入、`fsync`、关闭、`rename`、目录同步。保存失败时回滚内存状态并返回错误。
- 所有 CRUD 在同一互斥锁内完成，先修改内存副本、落盘成功后再替换可读状态；读取返回副本。
- 文件损坏时保留原文件并让存储进入不可用状态。启动配置是用户数据，不能像可重建的推送密钥那样改名重建。
- 不可用状态在进程生命周期内保持；手动修复、删除文件或停止另一实例后需要重启服务。API 的 503 错误文本包含不可用原因与 `<state_dir>/launch-configs.json`，供设置页提示；不包含环境变量值。
- 本存储不读取 TOML 预设，也不生成默认配置；内置预设继续由 `GET /api/presets` 提供。

### 3. API 契约

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/launch-configs` | 返回配置摘要数组（含 `envNames`，不含 `env`）；存储不可用时 503 |
| GET | `/api/launch-configs/{id}` | 返回单条完整配置（含 `env`）；不存在 404 |
| POST | `/api/launch-configs` | 请求体 `{name, cmd, env}`；201 返回完整配置 |
| PUT | `/api/launch-configs/{id}` | 全量更新 `name`、`cmd`、`env`；200 返回完整配置 |
| DELETE | `/api/launch-configs/{id}` | 删除；204；不存在 404 |

- 摘要形状：`{id, name, cmd, envNames, createdAt, updatedAt}`，`envNames` 为变量名按字典序排列的数组，空时为 `[]`。完整形状：`{id, name, cmd, env, createdAt, updatedAt}`。
- 创建与更新使用现有 `decode`：拒绝未知字段、只接受一个 JSON 对象、请求体上限 64 KiB。`env` 缺省视为空映射；`cmd` 缺失或为空、名称为空均为 400。
- 状态码：校验失败 400；名称冲突 409；ID 不存在 404；存储不可用、文件损坏或锁冲突 503；落盘失败 500 且内存回滚。错误沿用 `{"error": "..."}`。
- 更新为整体替换：未提供的 `env` 清空，未提供的 `name`/`cmd` 视为无效而不是“保留原值”。`id`、`createdAt` 由服务端保持，`updatedAt` 刷新。编辑对话框必须先读取单条完整配置再保存，避免用摘要回填导致环境变量被清空。
- 读取顺序稳定，便于设置页展示与测试。错误与日志中不输出环境变量值。
- 路由注册在 `Server.routes`，自动继承 `/api/*` 的认证、Host、Origin 与 panic 恢复；不新增权限边界。
- 并发写入由存储互斥锁串行化；本期的并发编辑采用后写覆盖，不做版本号或冲突合并。

### 4. `POST /api/sessions` 的 `configId`

请求结构增加一个可区分“未提供”和“空字符串”的字段（Go 侧使用 `*string`）：

```json
{ "configId": "k3m9q2x7", "cwd": "/home/u/proj", "name": "可选" }
```

- `configId` 存在时，`preset` 必须为空字符串或缺省，`cmd`、`args` 必须为缺省或空数组，`env` 必须为缺省、`null` 或空对象 `{}`；否则 400。空字符串 `configId` 也返回 400，避免静默回退到其他启动方式。
- 校验顺序：解码（400）→ 字段互斥（400）→ 读取配置（存储不可用 503，未知 ID 404）→ `session.ValidateEnv`（400）→ 现有目录/工作树校验（400/409/503）→ 启动会话。前四步都不做目录或 Git 操作。
- 启动时把配置的 `cmd` 与 `env` 复制后传给 `Workspace.CreateSession(ctx, cwd, "custom", cfg.Cmd, nil, name, workspace, cfg.Env)`。`args` 必须为 `nil`，因为完整 argv 已包含追加参数。
- 会话信息记录 `preset: "custom"` 与完整 `cmd`；`env` 不进入会话信息。本期不增加 `configId` 字段，避免改变 `SessionInfo` 契约。
- 删除或更新配置不会影响已启动会话，因为 argv/env 已在启动时复制并传入 PTY。
- 现有 `preset`/`cmd`/`args`/`env` 路径保持原样；内置预设、CLI 与脚本无需改动。

### 5. 设置页管理

- `Settings.svelte` 新增 `id="launch-configs"` 卡片，位置在“快捷指令”之后；`#launch-configs` 加入现有深链接滚动目标。页面顶部说明改为区分：快捷指令、草稿和预览只保存在当前浏览器；启动配置保存在服务端并在设备间共享；公网访问与通知推送的现有说明保留。
- 卡片说明内置预设来自配置文件 `[[presets]]`、需编辑配置并重启才会变化，启动配置是可在此管理的独立副本。卡片不列出或编辑内置预设。
- 列表展示名称、命令预览与环境变量数量（来自 `envNames`）；提供新建、编辑、删除（确认对话框）与空状态。达到 100 条时禁用新建并提示上限。加载失败或 503 时显示不可用原因与文件路径，禁用写操作，但页面其他设置仍可用。
- 编辑器组件 `LaunchConfigDialog.svelte`：名称 `Input`、命令等宽 `Textarea`、环境变量行编辑器。编辑已有配置时先 `GET /api/launch-configs/{id}` 读取完整配置，加载期间禁用保存；读取失败时显示错误而不打开可保存的表单。
- “从内置预设填入”：读取 `GET /api/presets`，把预设 `cmd` 与用户追加参数合并成完整 argv 写入命令框；名称为空时预填预设的 `label`。保存后是独立副本，不再关联预设。
- 命令在保存时用 `parseArgs` 解析。新增 `quoteArg`/`joinArgs` 纯函数负责“argv → 可再次解析的文本”：对含空白、引号、反斜杠、`$` 或空字符串的参数加引号并转义，保证编辑往返后 argv 完全一致。该函数放在前端工具模块中，供设置页、新建会话页与 Node 单元测试共用。
- 环境变量行：名称输入、值输入（默认 `type="password"` 遮挡，提供可访问名称明确的显示/隐藏按钮）、添加与删除。名称前端即时校验同一正则并拒绝 `WEBMUX_SESSION_ID`，值与数量上限与服务端一致；服务端仍做最终校验。
- 命令预览不包含环境变量值；列表和截图不得展示密钥。删除确认只显示名称与命令预览。
- 保存失败时对话框保持打开并显示错误；409 提示重名并保留输入；503 提示存储不可用。
- 设置页的快捷指令、草稿、预览等浏览器本地设置保持不变。

### 6. 新建会话页

- `SessionList.svelte` 继续加载 `GET /api/presets`，并加载 `GET /api/launch-configs`（摘要，不含环境变量值），传给 `NewSessionSheet`。启动配置加载失败不影响内置预设与“新建会话”按钮可用性。
- 启动方式分两组：“内置预设”（按 TOML 顺序显示 `label`，`allowArgs` 预设保留现有“追加参数”输入，提交 `{preset, args}`）与“我的启动配置”（显示名称、命令预览与环境变量数量，提交 `{configId}`）。两组都与目录/工作树/会话名的现有选择组合。
- 折叠的“临时命令（不保存）”只承载一次性的自定义命令，提交 `{preset: "custom", cmd}`，继续把命令文本记在 `customCommand`，不写服务端。
- 记住上次选择：浏览器本地键 `lastLaunch` 保存 `preset:<name>`、`config:<id>` 或 `custom`，不缓存配置内容。首次加载时若没有 `lastLaunch` 而存在旧 `lastPreset`，按 `preset:<lastPreset>`（或 `custom`）迁移并删除 `lastPreset`。记住的选项不存在时回退到第一条内置预设。
- 没有启动配置时，“我的启动配置”组显示简短空状态与“前往设置创建启动配置”链接（`/settings#launch-configs`）；存储不可用时该组显示原因，内置预设与临时命令不受影响。
- 启动配置加载期间该组不可选，避免发送空 `configId`；内置预设不等待启动配置加载。
- 桌面 Dialog 与移动 Drawer 共用同一表单，两组选项在窄屏可滚动且无横向溢出。

### 7. 校验与安全

- 认证、Host、Origin 校验与单用户模型不变；启动配置接口只通过已认证的 `/api/*` 暴露。
- 启动配置可以执行任意命令，与现有自定义命令接口一致，不新增提权或沙箱承诺。部署仍应限制在 loopback 或可信 VPN。
- 环境变量可能含密钥：文件权限 0600、目录 0700；列表接口不返回值，只有单条读取与创建/更新响应返回；新建会话页不请求值；服务端不记录请求体或配置中的值；设置页默认遮挡；命令预览和 E2E 截图不得包含值。
- 显式 `env` 覆盖服务进程环境中的同名变量，`WEBMUX_SESSION_ID` 不可覆盖；不复制调用方环境。
- 请求体严格 JSON、64 KiB 上限、数量与单项长度限制共同防止无界存储与超大响应；读取时也校验文件内容，损坏文件不进入可用状态。
- 文件锁防止两个实例并发改写同一文件；锁冲突只禁用本功能。
- 不新增 CORS 例外、静态文件或未认证的诊断端点。

### 8. 备选方案

- 首次启动把 TOML 预设种子为启动配置：后续新增预设与默认预设修正（如 #90）不会到达已种子的用户；不采用，改为内置预设实时并列。
- 种子 + 手动“重新导入”：仍然无法跟随已存在预设的修改；不采用。
- 写回 `config.toml`：会破坏注释和手写格式，且需要重启才能生效；不采用。
- 仅保存在 `localStorage`：无法跨设备，与“服务端持久化”的需求冲突；不采用。
- 只保存预设名与追加参数：预设变化或删除会让已保存配置失效，且无法表达完全自定义命令；不采用。
- 列表返回完整 `env`：每台打开新建会话页的设备都会收到密钥值；不采用。
- 损坏文件自动改名并重建（push 存储的做法）：会静默丢失用户配置；不采用。
- 依赖 `repositories.lock` 或不加锁：该锁失败时服务仍运行，无法保护本文件；不采用。
- 单独的秘密存储或加密：本期单用户与 0600 文件边界足够，增加复杂度且没有明确威胁模型；不采用。
- 在 `SessionInfo` 中加 `configId`/配置名：本期没有必要，且会扩大契约面；后续需要时再加可选字段。

## Risks / Trade-offs

- [已保存配置与 TOML 预设漂移] → 设置页与编辑器提示“保存的是创建时的命令副本”；需要跟随预设的用户直接使用内置预设。
- [两组启动方式增加选择成本] → 内置预设在前且默认选中，启动配置为空时只显示一行空状态；不引入额外层级。
- [环境变量以明文保存在状态文件] → 文件 0600、目录 0700、列表不含值、值默认遮挡、日志不记录；但这仍不是加密存储，拥有服务账户文件访问权的用户可以读取。
- [损坏或锁冲突导致功能不可用直到重启] → 保留原文件与避免并发覆盖优先于可用性；错误信息给出原因与路径，会话服务和内置预设不受影响。
- [`api.New` 增加必需参数会波及大量测试与调用点] → 以编译错误为准逐个更新，并保留一个不依赖启动配置的测试构造路径；主要改动是机械接线。
- [64 KiB 请求上限小于“128 项 × 8 KiB”的理论上限] → 这是有意的整体边界；前端提前限制并在超限时给出可读错误。
- [删除配置后无法从会话反查配置] → 本期通过 `cmd` 完整值仍可还原命令；配置名与首页一键启动留到下一期。
- [并发编辑后写覆盖] → 本期单用户场景接受；后续如需多端同时编辑再增加版本号或冲突提示。
- [环境变量拼写错误不会在启动时被程序发现] → 与现有 `env` 接口行为一致，只校验名称与 NUL；不尝试解释变量语义。

## Migration Plan

- 没有旧服务端数据需要迁移；`launch-configs.json` 不存在时为空列表，首次创建配置时才写入。
- TOML `[[presets]]` 的语义与 `GET /api/presets` 不变，现有部署无需修改配置文件。
- 浏览器端：`lastPreset` 迁移为 `lastLaunch` 后删除；`customCommand` 继续作为临时命令内容；不把浏览器旧值自动上传为服务端配置。
- 现有客户端与脚本继续使用 `preset`/`cmd`/`args`/`env`；服务端保持兼容。
- 回滚：服务端回退版本会忽略 `launch-configs.json` 与锁文件，不影响会话创建；旧前端读取 `lastPreset` 不存在时回退到第一条预设。若文件损坏，可手动修复或删除后重启。
- 实现顺序：M1 存储 → M2 API 与接线 → M3 前端 → M4 测试与文档；每步保持可编译、可回滚。
