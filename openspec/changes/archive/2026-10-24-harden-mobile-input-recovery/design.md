## Context

动机见 proposal.md。与实现相关的现状：

- `internal/hub.Attach` 为每个连接起一个读 goroutine、一个输入 goroutine 和唯一的写循环；输入经容量 16 的通道交给 `Session.WriteContext`，后者以 `inputGate` 串行化写入并在连接取消时放弃。
- `Session.Attach` 在会话锁内捕获快照并登记订阅者，保证回放与实时流之间没有缺口；`Replay` 清空订阅队列后重新回放。
- `RingBuffer` 只保留最新若干字节，不记录绝对位置；会话 ID 为 40 位随机值，没有代际标识。
- 前端 `useTerminal` 在页面隐藏时丢弃输出并标记 `stale`，前台时 `ws.ts` 强制重连，靠全量快照恢复。
- `attention.go` 已有 `terminalReplyOnly`，用于识别 OSC/DCS 与设备报告类终端自动回复。

## Goals / Non-Goals

**Goals:**

- 让用户能区分“只在本机”“服务端已收到”“已完整写入终端”“结果未知”，且 ACK 丢失后重发不会重复写入。
- 草稿在刷新、页面回收、认证失效后可恢复，发送仍由用户显式触发。
- 短暂断线、切到后台再回来时不清屏、只传缺失数据。
- 多设备同时打开时布局稳定，设备查询只被回答一次。
- 旧行为在无查询参数的连接上仍然可用；不新增依赖。

**Non-Goals:**

- “agent 已接受或执行成功”：PTY 写入完成不代表 agent 处理了输入，本变更不展示这一层。
- 完整终端状态 checkpoint、服务端终端仿真、跨服务重启恢复、tmux 等会话后端。
- 多人协作语义（多人光标、权限、排队）；控制权只针对 WebMux 客户端，tmux 原生客户端的本地输入不在范围内。
- 把普通按键变成需确认的任务。

## Decisions

### 1. 运行代际与输出 offset

每个会话启动时生成 16 位十六进制 `generation`，写入 `SessionInfo`。环形缓冲记录累计写入字节 `total`，`Range()` 返回 `[total-size, total)`。offset 与代际一起才有意义：同 ID 的另一次运行（理论上可能复用 ID）不会被误续接。

### 2. 位置帧先于回放；增量数据复用输出帧

服务端每次回放（附着或 0x02 重新同步）先发 0x04 位置帧 `{generation, mode, start, end, truncated}`：

- `mode: "reset"`：随后是 0x01 快照，覆盖 `[start, end)`。
- `mode: "append"`：随后（若有）是一个普通 0x00 输出帧，内容恰为 `[start, end)`。

客户端在连接 URL 上携带 `generation` 与 `offset`；代际一致且 offset 仍在保留范围内（含等于 `end`）时续接，否则全量。缺失尾部复用 0x00 帧，客户端不需要新的数据路径；位置帧与快照/尾部在同一把锁内入队，延续“无缺口”保证。`truncated` 表示最早输出已被覆盖，菜单中的“复制全部缓冲”据此提示。

**备选**：在每个 0x00 帧前加 offset 头。拒绝原因：每帧多 8 字节且需改写合并逻辑；由于回放与订阅原子登记，客户端按字节累加即可得到精确 offset。

### 3. 客户端的 offset 只计“已交给 xterm 的字节”

页面隐藏时不再写入 xterm 但 offset 停在最后写入处，并保持 `synced`；回到前台重连即从该处续接。只有收到快照（且页面可见）才重置 offset；收到无法匹配的 `append` 时放弃续接并请求 0x02 全量同步。已同步的终端重连期间不显示“正在连接”遮罩，内容保持可见。

### 4. 提交帧：JSON 头 + 原始字节

客户端 0x03 载荷为一行 JSON `{id, generation, bodyBytes}`、换行，再接正文字节和提交键字节。终端字节不进入 JSON，遵守“PTY 数据保持二进制”的约定。正文由客户端按 xterm `paste()` 的规则准备（换行转 CR、按应用状态包裹 bracketed paste），保持与原草稿发送完全相同的线上字节。

服务端在输入 goroutine 中处理提交：在会话锁内查重并登记记录（`received`，并通知该客户端所有连接），随后以 `writeParts` 在一次 `inputGate` 持有期间依次写正文和提交键，其他连接的输入不能插入其间。结果为 `written`、`partial`（部分字节已写入）或 `failed`；代际不符直接 `failed/generation`，帧格式错误 `failed/invalid`。

**提交与连接解耦**：一旦登记为 `received`，写入使用 `context.WithoutCancel`，仍受 10 秒写期限和会话退出约束；连接断开不会让已收到的提交半途取消。尚在通道中、未登记的提交随连接一起丢弃，查询时为 `missing`——与“未收到”一致。连接收尾仍会等待输入 goroutine，最长受写期限约束。

### 5. 提交记录、查询与幂等重发

每个会话在锁内维护最多 256 条、保留 30 分钟的提交记录。重复 ID 不再写入，只回报已记录状态；0x04 查询逐个回报状态，无记录时为 `missing`（未送达或已过期）。最终状态发往提交客户端的全部连接，因此重连后的新连接也能收到仍在写入中的提交结果。

客户端在连接建立后查询所有未确认的提交；连接中断时把它们标为“结果未知”。草稿的“按原提交重发”复用同一 ID，因此服务端若已收到，不会重复写入。`failed`/`missing` 释放锁定，正文成为普通草稿，再次发送使用新 ID。

### 6. 草稿持久化

`draftStorage.ts` 以 `webmux.draft.<sessionId>` 为键，Zod 校验 `{v, sessionId, generation, text, savedAt, submission}`。localStorage 天然按服务器 origin 隔离；代际在终端页得知后绑定，不一致时保留正文但丢弃提交记录。7 天未修改过期，打开存储时清理过期、损坏或键名不符的条目；会话列表快照到达时删除已不存在会话的草稿。正文超过 200 000 字符时只保留在内存，界面提示。所有访问容忍存储不可用。

认证失效与页面卸载只清内存条目，不删除本机保存；会话被移除或终端报告会话不存在时删除。恢复的非空草稿自动打开草稿面板并显示“已恢复本机草稿 · 目标”。未确认提交恢复为“结果未知”并在连接后查询；若已写入，清空草稿并提示“上次提交的草稿已写入终端”。

### 7. 控制端

客户端 ID 存于 `sessionStorage`（每个标签页一个，刷新与重连保持），设备名由 UA 推断（如 “iPhone · Safari”），服务端清洗控制字符并截断为 40 字符。规则：

- 附着时若无控制端，该客户端成为控制端；同一客户端的重连保持控制。
- 0x00 用户输入、0x03 提交、0x05 接管把控制权交给发送方客户端。
- 控制端客户端最近附着的连接是唯一有效的控制连接：复制标签页会复制 `sessionStorage`，可能出现同 ID 的两个连接，若都被认作控制端，不同视口会交替 resize 形成反馈环。它断开时由同客户端剩余的最新连接接替；全部断开时控制权空缺，并不转交给剩余观察端，避免其布局随之改变。前端另以存活标记检测复制：页面离开（`pagehide`）时清除标记，新页面若仍看到标记即为复制并换用新 ID。
- 只有控制端的 0x01 resize 生效；尺寸变化时广播 0x06 控制帧，观察端据此把 xterm 调整为 PTY 网格而不 fit 容器。
- 输入来源由客户端标明：xterm 内核只在用户输入时于 `onData` 之前同步触发 `onUserInput`，据此把用户输入以 0x00、自动应答以 0x06 发送。不按字节模式推断，因为同样的字节可能来自按键（Shift+F3 与光标位置报告都是 `ESC [ 1 ; 2 R`）。服务端只把“负责回复的连接”的 0x06 写入 PTY：控制连接；无控制端时为最早附着的连接。0x06 不取得控制、不清除关注提醒。
- resize 的所有权检查与 resize 在同一临界区内完成（`ResizeFrom`）；每次回放先发 0x06 控制帧，观察端在解析历史之前采用网格。

观察端宿主允许溢出滚动；触屏单指拖动先平移宿主（顶部行、左右列），到边界后再滚动终端历史。界面在观察时显示“观察中 · <设备>控制输入与尺寸”与“接管控制”按钮；软键盘按钮在观察时先接管。

**备选**：控制端断开即转给最早的观察端。拒绝原因：手机锁屏的短暂断线会让桌面立即 resize，正是要消除的布局抖动。

## Risks / Trade-offs

- [观察端在 TUI 中滑动] → 交替屏幕下的滚轮会被 xterm 转为方向键输入，从而接管控制。这是用户输入的真实语义，暂不特殊处理。
- [记录过期后的重发] → 超过 30 分钟或 256 条后记录被淘汰，`missing` 可能掩盖“其实已写入”。界面文案明确“可能未送达，或记录已过期”，由用户检查终端后决定。
- [自动回复只由一端负责] → 若负责端的 xterm 尚未回放到查询位置，回复会稍晚到达；比重复回复更安全。
- [同一设备多个标签页] → 视为不同客户端，各自需要接管；符合“标签页即一个终端视图”的直觉。
- [本机保存的隐私] → 草稿正文以明文保存在浏览器存储中。单用户部署，提供关闭开关与清除入口。

## Migration Plan

协议向后兼容：无查询参数的连接得到随机客户端 ID 并按新规则参与控制，旧客户端忽略未知帧类型。前端与后端一起嵌入发布，无数据迁移；回退只需回退二进制，浏览器中的草稿键会在 7 天后过期。
