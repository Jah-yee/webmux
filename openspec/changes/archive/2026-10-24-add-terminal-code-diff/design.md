# Design

## Context

动机见 [proposal.md](proposal.md)。现有实现基于 `c3b46cd`：

- `Terminal.svelte` 和 `useTerminal` 持有唯一 xterm/WS、VisualViewport、上传、粘贴、软键和全屏；标签切换需要处理隐藏尺寸，不能卸载终端。
- `SessionInfo.cwd` 是启动目录，workspace 关联可空；`internal/workspace` 已实现 Git 定位、清单、工作树和删除协调，注册存储能力与 Git 可用性分开。
- `/api/fs/dirs` 与 DirectoryPicker 用于选择启动目录，只返回目录并允许系统路径导航，不能作为新代码区的文件范围合同。
- 现有 Git runner 有超时/取消进程组，但输出使用无界 bytes.Buffer；新的大内容读取需要有界实现。
- `api.ts` / `schemas.ts` 集中处理认证、401 和 Zod，终端输入仍通过二进制 WS。`paste` 当前返回 void，`ws.send` 可报告本地是否可发送，没有远端确认。
- 当前已有 shadcn Command、Collapsible、ScrollArea，尚无 Tabs、Resizable 或代码阅读器；E2E 可复用真实临时 Git/PTY/服务夹具。

### Confirmed Product Decisions

用户已确认：只读浏览、文件路径搜索、Diff 与发送代码位置；当前工作树和未提交修改；完整文件以及没有变化区域的展开；多个文件标签；手机“终端 / 代码”外层切换；忽略项默认隐藏且可显示，.git 内部数据始终隐藏；自动检测更新并提示，用户点击后刷新，保持阅读位置。

工程默认值：1024px 桌面断点、统一 Diff、上下文每次展开 30 行、可见时 5 秒检测、20 个文档标签上限。文件内查找、跳转行、只读语法高亮和可调整分隔线作为浏览体验的一部分。第一版不选分支/提交、不做编辑保存、全库内容搜索或 Git 写操作。

## Goals / Non-Goals

**Goals:**

- 以“浏览根 → 文档身份 → 内容版本 → 阅读/比较/引用”组织能力，文件不需要有修改才能读取。
- 文件导航、内容快照、Git 比较、终端输入各自保持清楚职责；后续来源扩展不需要重写选区和引用模型。
- 固定内容版本后再展示全文或按需展开上下文，避免旧 diff 和新文件混合。
- 检测和刷新分离，避免 agent 持续写入时阅读内容跳动。

**Non-Goals:**

- 不引入通用 IDE、LSP、代码执行、Markdown/HTML 主动预览或文档编辑。
- 不跟踪运行时 cd，不浏览其他工作树/任意系统目录，不创建 Git 提交快照。
- 不承诺外部并发写入的跨文件事务、消息到达 agent 的确认或服务器重启后的文档恢复。
- 代码内容不落入持久存储、日志、localStorage 或 IndexedDB；文本比较不写临时文件。

## Decisions

### 1. 页面以代码阅读为中心组织

桌面示意：

```text
┌────────────终端────────────┬────────────代码区（可调宽）────────────┐
│ agent 输出与输入          │ [文件] [修改]  搜索路径  刷新          │
│                           │ ┌───────────┬──────────────────────┐ │
│                           │ │目录树/    │ main.go × | api.ts × │ │
│                           │ │修改列表   │ 路径面包屑 + 来源     │ │
│                           │ │           │ [完整文件] [Diff]     │ │
│                           │ │           │ 代码、行号、查找      │ │
│                           │ │           │ 更新提示 / 发送位置   │ │
│                           │ └───────────┴──────────────────────┘ │
└───────────────────────────┴─────────────────────────────────────┘
```

宽度至少 1024px 时采用左终端、右代码区，默认约 50/50，分隔线支持拖拽和键盘调整，约束终端与代码最小可用宽度。代码区可折叠；内部文件导航可收起。更窄时外层“终端 / 代码”，代码页使用文件标签加可展开导航面板选择“文件 / 修改”；选择文件后收起导航，为阅读留出空间。长路径面包屑可滚动，长代码在阅读区滚动，整个页面不横向溢出。

终端宿主始终挂载，隐藏时停止 fit/resize 而继续接收输出；重新显示后等待布局并发送有效尺寸。软键、终端选择浮层和文件上传拖放仅在终端区域生效，代码区域保留自己的选中/查找操作。代码导航不抢终端输入焦点。

文档标签键为 contextId、原始相对路径和来源，来源包括 worktree、index、head；不同来源有显著标签，同一文档复用标签。重复打开时发现新版本仅提示更新，不覆盖原标签的阅读内容。每标签持有模式、snapshotId、滚动行锚点、查找词、有效选区和更新状态；切换只改变活动文档，不清空其他文档。上限 20 个，超限要求先关闭一个，不静默淘汰标签；内容快照另受内存限制。

### 2. 增加独立的代码读取服务，复用 workspace 的 Git 能力

在 `internal/codeview` 集中实现根绑定、目录/搜索、内容快照和变更检查，由 `cmd/webmux/main.go` 显式构造并注入 API。session manager 只提供会话信息读取与移除通知，不依赖代码浏览服务；workspace 提供必要的只读 Git 定位/来源查询，继续独占现有 Git 写操作与删除协调。

Git 可用时，从启动 cwd 解析当前工作树顶层与工作树自己的 Git 管理目录；未注册仓库同样适用。普通目录或缺少 Git 时以启动 cwd 为根，目录/全文/引用可用，差异能力降级。已有 workspace 关联时检查根一致。根在首次成功解析时绑定规范路径和文件系统身份；后续身份失效显示 unavailable，不自动重绑同名目录或切到其他来源。无 Git 的绑定不在后台悄悄扩展到更大的父仓库。

nodeId 编码根内原始相对路径，与 changes 条目身份独立。读取根据会话、contextId、根边界和目标类型验证，不要求 nodeId 在变化列表中。变化条目 changeId 另含 staged/unstaged/untracked 来源、双方路径与元数据。

目录逐层读取；默认隐藏未跟踪的 Git 忽略项，但不隐藏已跟踪文件。includeIgnored 只影响文件树/路径搜索，不改变 Git changes。始终排除 .git 文件/目录及已知 Git 管理路径，.github 等点目录正常展示。忽略项开关关闭后，已有打开标签仍可见且标明忽略状态；此开关是导航过滤，不是访问授权。

符号链接显示链接文字，不跟随读取目标；子模块/嵌套仓库显示边界条目。常规文件从已绑定根以逐段不跟随链接的方式打开，拒绝 device/FIFO，检查原始路径字节和目标身份。普通目录没有 Git ignore 信息时明确显示该能力不可用，不能假称已过滤所有忽略项。

### 3. 目录、文件、差异和内容版本分开建模

所有新路由使用 `/api/sessions/{id}/code` 前缀和原 API middleware。建议合同：

| 路由                                               | 作用与关键字段                                                                                                                     |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `GET /context`                                     | contextId、rootPath、rootKind、browseAvailable、diffAvailable、ignoreAvailable、reason                                             |
| `GET /tree?contextId&nodeId&includeIgnored&cursor` | 单目录 children、nextCursor、limited、checkedAt；条目含 nodeId、path、kind、gitStatus、ignored                                     |
| `GET /files?contextId&q&includeIgnored`            | 按文件名/路径过滤的有界结果，含 complete/limited 和 checkedAt                                                                      |
| `GET /file?contextId&nodeId`                       | 抓取工作区文件；返回 document、snapshotId、contentVersion、kind、text、lineCount、checkedAt                                        |
| `GET /changes?contextId&cursor&q&nodeId&group`     | 每页 200 项的三组 entries、nextCursor、匹配 total、contentVersion；支持路径 / 精确 nodeId / 分组筛选                               |
| `GET /diff?contextId&changeId`                     | 成对 snapshotId、old/new 原始完整文本和文档描述、contentVersion、checkedAt                                                         |
| `GET /snapshots/{snapshotId}/file?side`            | 读取已捕获完整文件或 Diff 指定侧，不重新读取实时路径                                                                               |
| `POST /check`                                      | 只读批量检查；body 含 contextId、打开的 snapshotIds、可见目录标识和 changesVersion；返回 updated/unchanged/missing/expired/unknown |

context 结果区分浏览能力和 Git 差异能力。文件 kind 为 text/binary/symlink/too-large/unsupported；diff 另有 metadata/unmerged，非文本不伪造行号。文档描述含相对路径、实际来源 worktree/index/head/empty、可空 OID、contentVersion。来源选项只来自服务端当前工作树，第一版不接收任意 revision。

缺少会话返回 404；非法参数/越界返回 400；根或来源改变返回 409；快照失效返回 410；列表/搜索响应超限可返回 413；请求超时返回 504。权限/读取故障与“确实为空”区分；普通目录差异不可用在 capability 中表达。已被删除的文件可保留旧标签并标 missing，不自动关闭。

快照是会话范围的随机标识，所有快照读取与 check 校验归属；客户端无法用另一会话标识读取。原始路径字节用于文件操作；非法 UTF-8 路径以转义形式展示并禁用无法无损表达的位置发送。JSON 输出经 schemas.ts 验证；api.ts 统一取消和 401，终端协议不变。

修改列表采用流式 NUL 解析，按未暂存 / 已暂存 / 未跟踪的稳定 Git 顺序统计匹配总数、计算全列表摘要，仅保留 200 条当前页；不再因超过某个总项数或累计 2 MiB 输出而拒绝整个仓库。status / ignore 查询同样逐条处理，只保留当前目录所需元信息。单条不完整 / 异常记录仍拒绝，请求期限与并发保护保留。

分页游标绑定 contextId、完整列表版本、路径筛选 / nodeId / 来源组，版本变化返回 409；前端保留旧页并提示刷新，不跨版本追加。修改列表支持来源 / 路径筛选、滚动按需加载和显式加载下一页，固定行高并虚拟化可见区域，路径以标题和文档呈现完整名称。键盘方向键 / Home / End 可导航已加载条目。服务端过滤遍历完整流，因此未加载页的文件也可被找到；全文切 Diff 和刷新使用精确 nodeId，直接 Diff 查找完整流，批量检测只保留所需快照条目，不依赖当前页。流式分页每页仍扫描 Git 元信息以计算版本和总数，避免在服务端缓存无界全表。

### 4. 固定原始内容后生成 Diff 和可展开区域

完整文件读取先有界捕获字节、文件信息和内容摘要，返回 immutable snapshot。读取前后核对文件身份、大小和修改信息，检测到写入则重试一次或返回 409；不承诺任意外部写入下的跨文件原子性。

Diff 先解析双方版本：unstaged 为索引 blob 与工作区捕获，staged 为 HEAD blob 与索引 blob，untracked 为 empty 与工作区捕获。HEAD/index 用解析到的不可变 OID 读对象，工作区用同一有界读法；比对读取前后源身份，发生变化重试或冲突。重命名、模式、unmerged 等元信息来自 Git NUL 机器输出。

所有 Git 查询使用 argv、非交互环境和 `GIT_OPTIONAL_LOCKS=0`，路径用 literal pathspec 与 `--` 隔离，不修改 safe.directory，也不允许只读状态查询顺带刷新写入索引。只读 runner 为 status / diff 临时禁用配置中的 clean / process filters，并禁用 fsmonitor；不修改用户配置。

服务端只捕获并返回同一 snapshotId 下的两份原始完整文本与来源元信息，不生成 patch、hunks 或 gaps，不使用比较临时文件。浏览器在独立 Web Worker 中调用成熟的 jsdiff（`diff` 包）`diffLines`，基于捕获双方计算统一 Diff；快照一致性由成对文本保证，与算法运行位置无关。服务端仍负责 Git 修改列表、OID/模式/重命名、文本属性与权限边界。

比较设置 `stripTrailingCr: true`，把 LF/CRLF 的行尾差异归一化；保留原始快照字节和末尾换行语义。不执行自定义内容转换；遇到必须通过过滤器或编码转换才能比较且无法维持原始行映射的条目，显示不支持差异转换，原始完整文件仍可阅读。差异块划分可能与 Git CLI 不同，不承诺补丁输出完全一致。

jsdiff 的行数结果映射回各侧原文件，新增/删除行只含本侧行号，no-newline 标记没有代码行号。浏览器在局部模型中保留三行上下文并折叠其余等同行，包括文件头尾；向上/向下每次 30 行或全部展开只读取该模型，不请求服务器，也不读取当前磁盘。展开只替换仍存在的 gap，重复操作不复制行。服务器已知快照失效后禁用展开和引用，要求刷新，保留已显示内容。

仅代码区可见且标签活动时启动计算；切换标签、隐藏代码区、改变快照或销毁组件时终止未完成 Worker。每标签缓存当前 snapshotId 的计算模型，回到相同版本沿用折叠与阅读状态。Worker 回包携带 snapshotId，经 Zod 校验后仍核对当前文档与取消状态，过期结果不能覆盖新视图。jsdiff 详细比较预算 250ms，Worker 整体看门狗 10 秒；超限、启动或计算失败明确提示，可重试或查看两侧冻结全文，不提供截断结果。

“查看完整文件”使用该快照指定侧。文件树打开 worktree 全文后切 Diff，需要抓取比较对；若新侧摘要与原全文不同，提示更新并保留原视图，用户刷新后切换，不能静默换版本。已暂存索引全文、HEAD 旧全文以独立来源标签打开。来源切换是明确操作；无修改文件保留全文并提示无未提交差异。

服务器使用有界内存 LRU 保存原始文本及来源元信息，默认总计 64 MiB、单条最多 10 分钟，会话移除或服务关闭释放。容量达到上限时可回收旧快照，但 API 必须返回 410，禁止悄悄重读当前文件冒充原版本。浏览器保留已加载文本供只读查看，标记失效并暂停位置发送。该机制供短期阅读，不提供历史恢复功能。

### 5. 自动检查版本，明确刷新后才替换内容

代码区可见且页面前台时，每 5 秒批量检查打开文档及当前可见导航；首次显示、回前台、终端重连立即检查。一个客户端最多一个在途 check，同根并发检查合并；隐藏代码区、后台、离开页面取消或暂停。首次打开新文件需要读取内容，后续检查只回传版本/状态，不回传新全文。

打开的 worktree 文档用当前有界内容摘要检测变更；index/head 来源比较对应 blob/路径；同根 changes 列表和已展开目录状态有短期复用，避免多标签重复 Git。检测也受读取时限与并发上限约束，不能通过 PTY 每次输出触发。失败返回 unknown 并保留上次检查时间，不把失败当 unchanged。

有更新时显示文档标记和“内容已更新，刷新”提示，保留文本、滚动、查找与旧选区。已知 updated/missing/expired 的文档禁用位置发送。用户点击文档刷新或代码区“刷新全部”才获取新版本；内容变化清除选区，滚动以原可见行作为锚点并夹取到新文件范围。导航变化同样先提示再刷新；首次展开未加载目录按当前内容读取。

每个请求使用 session/context/document/requestSequence 校验；旧响应可更新对应仍打开且版本匹配的标签，不能覆盖活动新文档。关闭标签取消其读取，离开会话取消所有工作。新版本安装失败时保留旧快照并标识，不丢失当前阅读内容。

### 6. 使用只读阅读器并保持视图与位置模型分离

完整文件使用 CodeMirror 6 的 state/view/language/search 组件，启用 readOnly 与不可编辑模式、行号、只读查找/跳转及虚拟渲染。按需加载语言支持，不识别语言时纯文本；不加载编辑命令、LSP、lint 或执行能力。代码区懒加载，避免终端首次进入承担全部依赖。

Diff 使用独立结构化行/空白段展示，不把 patch 字符串当完整代码文档。语法颜色和引用依据对应侧的原文件行；大视图复用 CodeMirror 可见区渲染，展开全部或整份删除不要求一次创建几万 DOM 行。采用 jsdiff 算法与轻量行模型，避免直接使用将整个删除块构造成 DOM widget 的默认统一 Merge 视图。两种视图共享文档描述、选区和引用格式化逻辑，无需绑定同一个 UI 组件。

行选择以 document/snapshot/side/startLine/endLine 表达。完整文件的普通行、Diff 修改行、展开上下文都可以发送；跨 gap 必须先展开形成已显示连续范围。同版本全文/Diff 互换时映射相同行号；不同来源打开独立文档。原生文本复制与行级引用操作各自可用。

### 7. 引用只通过当前终端粘贴

预览和实际插入共享格式化函数，采用服务器验证的根加该侧路径形成绝对路径：

| 来源                                     | 示例                                                           |
| ---------------------------------------- | -------------------------------------------------------------- |
| 当前完整文件、未暂存新侧、普通新侧上下文 | `/repo/src/main.go:12-18 `                                     |
| 未暂存旧侧、完整索引文件、已暂存新侧     | `/repo/src/main.go:12-18（索引版本） `，删除旧侧额外标“旧版本” |
| 已暂存旧侧或完整 HEAD 文件               | `/repo/src/main.go:12-18（HEAD 旧版本） `                      |
| 文件级                                   | 路径加必要来源标签，无虚构行号                                 |

特殊路径使用 JSON 字符串引号/转义（例如 `"/repo/a b.go":12`），不插入原始 CR/LF/ESC/NUL，不包装为 shell 命令。非法 UTF-8 路径不能无损表示时禁用发送。引用针对展示快照，检测间隔内的外部变化不具备事务保证。

useTerminal 提供可观测的 paste 结果，检查初始化、connected、非 restoring、未退出，再经 xterm paste 保留 bracketed paste，使用现有 WS send 的本地结果。文档已知变旧/失效或当前标签不匹配时不进入粘贴。成功只提示已插入终端，失败保留选择，不追加回车、不清空输入、不自动补发。

手机成功切回终端并 fit，不强制 focus 唤起键盘；再次进入代码时恢复原文档。桌面终端与代码同屏，用户可以继续补充要求。Shell 与 agent 预设使用相同行为，不依赖第三方 API。

### 8. 对目录、搜索、内容和后台工作分别限量

初始限额作为实现常量与文档合同：

| 资源        | 初始限制与超限行为                                                               |
| ----------- | -------------------------------------------------------------------------------- |
| 单次请求    | 10 秒，含排队；取消清理 Git 子进程                                               |
| 目录        | 每页 200 条、单目录读取预算 10000 条；超出明确 limited，不声称列完               |
| 路径搜索    | 最多 200 个结果、最多检查 100000 个条目；达到时返回 complete=false，提示收窄路径 |
| 修改列表    | 每页 200 项，无总项数 / 累计输出限制；NUL 流式扫描，仅保留当前页或目标条目       |
| 单侧内容    | 2 MiB / 20000 行，超出不提供伪完整文本；二进制/编码不支持则显示摘要              |
| 浏览器 Diff | 每侧沿用内容限制；jsdiff 250ms 预算、Worker 10 秒看门狗；超限保留两侧全文入口    |
| 并发        | 最多两个重型读取/比较，错误摘要最多 8 KiB                                        |
| 快照        | 总计 64 MiB、最长 10 分钟，回收后明确失效                                        |
| 前端        | 最多 20 个文档标签；不将内容持久缓存到浏览器存储                                 |

对路径搜索的遍历按忽略策略跳过大依赖目录；显示忽略项是用户明确选择，但仍受预算限制。查找结果的 complete 字段与空结果含义分开。文件内查找只搜索已成功读取的完整文本。目录页游标与目录版本绑定，目录变化时提示重新读取，不拼接不一致的分页。

## Risks / Trade-offs

- [范围从 Diff 面板扩大为代码阅读工作区] → 先实现根/文档/快照，再接导航、全文和 Diff，共用引用模型，避免两套文件读取逻辑。
- [agent 写入使行位置过时] → 周期检查只提示，用户刷新后清选区；已知变旧文档暂停发送，展示时间与来源。
- [展开旧 Diff 时实时内容改变] → 比较与上下文来自同一冻结版本；过期明确失败，不临时换源。
- [忽略目录很大或文件包含敏感本地配置] → 默认隐藏、用户主动显示，逐层有界读取，内容不进日志或持久缓存。
- [新增阅读器增加包体] → 代码区与语言支持按需加载，保留纯文本降级；通过实际生产构建检查 chunk。
- [非 Git 目录没有 ignore 语义] → 明示能力差异，正常提供根内文件浏览，始终过滤 Git 内部数据。
- [快照内存与 Worker 生命周期] → 明确预算、超时、回收和 Worker 终止测试；快照失效不伪装恢复成功。
- [移动端阅读与终端触控冲突] → 代码与终端分开事件区域，终端常驻但不可见时不 fit，真机验证键盘行为。

## Migration Plan

1. 实施会话根与只读目录/内容服务、快照和 API 合同，再实现文件导航、多标签及只读阅读。
2. 接入冻结版本 Diff 与上下文展开、自动变化提示、任意行位置发送；始终复用原终端生命周期。
3. 同步产品文档，运行真实文件系统/Git/PTY、浏览器和 E2E，在 Linux/macOS 验证并记录真机可用证据。
4. 无数据库/配置迁移；回滚旧二进制即可恢复原页面。代码浏览不修改用户文件或 Git 索引，本 PR 现已包含实现、真实 Git / PTY / 浏览器测试与验收记录，见 tasks.md。
