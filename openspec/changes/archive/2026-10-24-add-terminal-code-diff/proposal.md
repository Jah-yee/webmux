# Proposal

## Why

用户在终端中运行 agent 时，需要像在 GitHub 上一样浏览整个工作树、阅读完整文件和差异上下文，并把任意代码位置交给当前 agent。将文件导航、代码阅读与 Diff 放在同一个代码区，可以连续完成理解代码、检查修改和反馈，而不局限于已经发生变更的行。

## What Changes

- 桌面左侧保留终端，右侧提供可折叠、可调整宽度的代码区；移动端使用“终端 / 代码”标签，代码区内部支持多个文件标签。
- 代码区提供“文件 / 修改”导航：按目录浏览、按文件路径搜索，打开未修改文件、未跟踪文件或变更文件；默认隐藏 Git 忽略项，可切换显示，始终隐藏 .git 内部数据。
- 完整文件视图支持语法高亮、真实行号、文件内查找和跳转行；各文件标签保留阅读位置，可关闭且重复打开不产生重复标签。
- 修改视图按未暂存、已暂存、未跟踪分组；支持统一 Diff、向上/向下展开未修改上下文、展开全部，以及打开指定比较侧的完整文件。没有 Diff 的文件和行同样可读、可选择。
- 从完整文件、Diff 修改行或展开的普通行选择文件、单行或连续范围，把位置插入当前会话输入；沿用准确版本来源和不自动回车语义。
- 自动检测代码变化并显示更新提示，已打开的阅读内容保持当前版本；用户点击刷新后更新内容、清除失效选区并尽量保持阅读位置。Diff 后续展开使用与已显示差异一致的内容版本。
- 按会话启动目录定位当前工作树，支持主工作区、linked worktree 和未注册仓库；普通目录会话以启动目录作为浏览根，仍可浏览文件，Git 差异能力单独降级。
- 本 PR 仅提交规划规格。第一版只读当前文件与未提交差异，不包含编辑/保存、分支/提交选择、仓库全局内容搜索、Git 写操作或 app/runtime 解耦。

## Capabilities

### New Capabilities

- `terminal-diff-review`：代码审阅工作区，包括目录/文件搜索、多文件完整阅读、未提交 Diff、上下文展开、版本一致性与响应式布局。
- `terminal-code-references`：从完整文件和 Diff 的任意可选代码行生成准确引用，并通过当前终端粘贴通道交给 agent。

### Modified Capabilities

无。当前没有主能力规范；本次在同一 draft 中扩展现有两份新能力规格，保持 change 标识 `add-terminal-code-diff` 和评审链接。现有 worktree 管理的目录归属与生命周期合同继续作为约束。

## Impact

- 后端：在独立代码读取服务中提供会话范围目录、路径搜索、文件内容与有界内容快照；复用 `internal/workspace` 的 Git 定位和只读比较能力。内容读取不再以“文件必须有修改”为前提。
- 前端：调整 `Terminal.svelte` 与布局样式，新增代码区导航、多文件标签、只读阅读器、Diff 展开及更新提示；扩展 `schemas.ts`、`api.ts` 和终端可见性/粘贴结果。
- 组件与依赖：复用 shadcn-svelte 导航/菜单/标签，采用 CodeMirror 6 提供只读完整文件阅读、查找与虚拟渲染；Diff 使用结构化行模型与独立展示，代码区按需加载。
- 验证：真实临时 Git/文件系统/PTY、浏览器及 E2E 覆盖文件浏览、版本固定的上下文展开、多标签、忽略项、变化检测、位置发送和原终端回归，覆盖 Linux/macOS。
- 文档：实施后同步 `README.md` 与 `WebMux.md`；没有持久化迁移或现有终端协议的破坏性修改。
