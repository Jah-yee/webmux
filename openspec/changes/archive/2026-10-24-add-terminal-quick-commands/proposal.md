## Why

手机上反复输入 `/resume`、`/new`、`git status` 这类常用命令或提示词既慢又容易打错，现有底部软键只能发送单个按键和符号。增加用户自定义的“快捷指令”，在设置里存好后一点即可发出，减少重复输入。

## What Changes

- 设置页新增“快捷指令”卡片：以列表展示已保存指令，可添加、编辑、删除（需确认）和上下移动排序；编辑使用对话框，字段为可选名称、必填指令正文（可多行）和“发送后自动回车”开关（新建默认关闭）。无指令时显示带“添加快捷指令”按钮的空状态。
- 首次使用（当前浏览器从未保存过列表）时预置 `/resume`、`/new` 两条无名称、开启自动回车的指令；用户保存过一次后（包括删光）不再自动补回。
- 入口为仅含闪电图标（⚡）的按钮，可访问名称与悬停提示为“快捷指令”：
  - 底部工具栏（软键栏）显示时，固定在软键栏最右侧，不随软键横向滚动，不改变软键单行布局；
  - 底部工具栏隐藏时（鼠标设备且未强制显示，或窄屏切换到代码视图），改在顶栏“草稿”按钮左侧显示；同一时刻只出现一个入口。
- 点击入口弹出菜单（软键栏向上、顶栏向下），按设置顺序列出指令：主行显示名称（无名称时显示正文首行），副行以等宽字体显示正文预览，开启自动回车的条目带回车标记。菜单底部固定“管理快捷指令…”入口，跳到设置页对应区域，设置页顶栏随之显示“返回终端”回到原会话；无指令时菜单显示空状态和“添加快捷指令…”入口。
- 选择指令后：直接输入模式下复用现有终端粘贴通路发送正文，开启自动回车时随后单独发送一次回车（CR）；草稿模式开启时，正文插入当前草稿光标处，不发送、不回车，与草稿模式“所有文本先进草稿”的约定一致。菜单顶部标明当前去向（“发送到终端”或“插入草稿”）。
- 未开启草稿且终端暂不可发送时（重连中、恢复中或已退出）菜单仍可打开，显示原因并禁用指令条目，“管理”入口保持可用；会话不存在时按钮禁用。发送失败或仅正文成功、回车失败时给出与草稿发送一致的错误提示，不自动重试。
- 快捷指令仅保存在当前浏览器（与现有设置页一致），同一浏览器多个标签页之间同步更新；不写入服务端，不新增后端 API 或依赖。

## Capabilities

### New Capabilities

- `terminal-quick-commands`: 快捷指令的设置管理（增删改、排序、校验、预置与浏览器本地持久化）、终端入口按钮（软键栏/顶栏互补显示）与菜单（内容、空状态、不可用状态）及发送语义（直接模式粘贴 + 可选回车、草稿模式插入草稿、失败提示）。

### Modified Capabilities

当前 `openspec/specs/` 无已登记主规格，无可修改路径。本变更遵循尚未归档的 `add-terminal-input-composer` 中“草稿模式开启时所有面向终端的文本统一写入草稿”的约定，将快捷指令作为新增文本入口纳入该规则，不改变其既有要求。

## Impact

- 前端页面：`web/src/pages/Settings.svelte` 新增快捷指令卡片与“返回终端”；`web/src/pages/Terminal.svelte` 接入发送逻辑并在顶栏放置桌面入口；`web/src/components/SoftKeys.svelte` 增加右侧固定区域；`web/src/styles.css` 增加两处入口的互补显示规则。
- 新增：快捷指令状态模块（浏览器本地存储读写与预置）、快捷指令菜单组件、设置页编辑对话框组件；`web/src/schemas.ts` 增加快捷指令 Zod 契约。
- shadcn-svelte：复用 DropdownMenu、Dialog、AlertDialog、Item、Empty、Input、Textarea、Label、Button、Badge；通过 shadcn-svelte CLI 新增 Switch 组件（基于已有的 bits-ui，不新增 npm 依赖）。
- 测试：新增 Node 单元测试（解析、规范化、预置）和 Playwright E2E（设置 → 终端发送、关闭回车、草稿模式、空状态、桌面顶栏入口）；调整既有软键单行布局 E2E 以覆盖新按钮。
- 不涉及 Go 后端、WebSocket 协议或服务端配置。
