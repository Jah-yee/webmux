## Context

动机与行为以 proposal.md 和 specs/terminal-input-composer/spec.md 为准。本变更跨页面、终端 hook、上传和代码引用，涉及输入归属和异步竞态，因此需要技术设计。

现有实现的约束：

- `App.svelte` 按会话 ID 创建带 key 的终端页，切换路由会销毁页面；页面局部变量不能承载跨路由草稿。认证失效由 `webmux:auth` 事件处理。
- `Terminal.svelte` 已有剪贴板读取失败弹窗，`insertReference()` 在成功直接粘贴后使手机返回终端。新模式不能沿用这一无条件切换。
- `useTerminal` 的 `paste()` 在初始化、连接、回放、退出状态检查后调用 xterm paste；底层 `send()` 处理修饰键并发送二进制输入。不可把所有底层字节无差别重定向，否则会把协议应答、转义序列或显式发送再次塞回草稿。
- `useUpload` 上传成功后等待前台、终端连接和回放恢复，再粘贴带 shell 引号的路径，最后聚焦终端。草稿目的地不需要这些终端条件；退出检查、取消、超时和原路径提示仍应保留。
- 代码引用已有格式化、版本有效性和特殊路径保护；手机“＋”与底部引用按钮应共用新的目的地，而不是新增一套引用操作。
- `useViewport` 已跟踪 VisualViewport；现有终端和代码共享固定生命周期，应保持宿主实例，不因草稿框显隐重建。

## Goals / Non-Goals

**Goals:**

- 一个用户文本目的地决策点，所有入口一致服从当前会话模式。
- 将“向当前输入目标插入文本”与“已确认发送到 PTY”分开，明确阻止递归和异步结果穿透。
- 草稿状态不依赖页面组件是否挂载，且认证和会话删除能确定性释放。
- 保留直接模式的原行为，不引入后端存储或第二套上传协议。

**Non-Goals:**

- 不模拟 shell 输入行、不从终端读取未提交正文；除用户显式草稿发送外，不为直接粘贴、代码引用或上传路径自动追加 Enter。
- 不实现命令执行队列、可靠投递确认、草稿跨刷新恢复或代码引用实时重定位。
- 不将终端控制字节转成草稿文本，不提供草稿模式内的完整终端控制界面。

## Decisions

### 1. 应用生命周期拥有每会话内存状态

新增小型 Svelte rune 状态模块，由 App 生命周期拥有，显式传递到需要它的页面；每个条目包含 `enabled`、`text`、`selectionStart`、`selectionEnd` 和单调递增的 `draftEpoch`。首次默认关闭；每次关闭→开启增加 epoch，手动关闭不清空正文；仅完整发送成功时清空正文、选区归零并设 `enabled = false`。选区使用原生 textarea 的 UTF-16 偏移，更新后校正到正文边界，不对 emoji 手工按字节截取。

路由卸载不删除条目；认证失效和 App 销毁清空全部。已确认移除事件、成功的权威会话快照中缺失或明确 missing/404 负责释放对应条目；请求失败、断线和普通进程退出不能删除。迟到操作携带原条目身份/生命周期代次，不能重新创建已经释放的条目。

不采用 localStorage/sessionStorage，也不把草稿塞入已有会话 API，避免意外持久化敏感输入。

### 2. Nested Vertical Resizable Split

`TerminalInputComposer.svelte` 使用既有 Textarea、Button 和清空确认 AlertDialog。模式开关位于顶栏代码切换按钮紧邻左侧，复用既有 shadcn Resizable，在桌面左右分割的左列内嵌套普通纵向分割：上方终端、下方非模态草稿面板，右侧代码区保持全高。不采用绝对定位覆盖层，不通过 pointer-events 穿透补丁模拟分割，也不放在终端/代码共享视图下方。两者之间的分隔手柄调整草稿高度，宽度跟随左列；开启和调高正常减少终端容器可用高度，由既有 fit/resize 通路更新 PTY，关闭后终端恢复左列全高。保持同一 xterm 宿主与终端实例，不以条件重建终端来切换布局。面板高度以 VisualViewport、左列容器和安全区约束，不根据正文无限增长；正文独立滚动，工具行保持可达。

草稿初始高度使用左列高度的 25%，沿用 160 px 最小高度，短视口下最终高度以左列的 80% 为上限，即 `min(max(0.25 * height, 160), 0.8 * height)`。仍允许用户拖动调高，初始面板不再与终端平分高度。

输入框内部保存 selection 和 composition 状态。引用、上传等外部插入使用最后有效选区；无有效选区则末尾插入。正文不自动增加换行或 trim，保留各来源已经生成的分隔和转义。外部插入不强迫唤起手机键盘。直接点击终端进行文本输入时，先将编辑目标转向草稿 textarea，确保输入法在原生编辑控件中完成。

桌面并排布局允许继续浏览代码、选行和上传，代码区尺寸不随面板开关或调高改变。手机终端视图使用相同上下分割；窄屏仅代码视图隐藏整个左列，但不修改模式、正文或选区；引用仍写入同一草稿，不强制切回终端，返回终端恢复分割与面板。手动关闭模式只隐藏面板并恢复直接输入，不清空未发送正文与选区。完整发送成功后清空并关闭面板，终端恢复左列高度；保持当前代码视图，不唤起终端键盘。

### 3. 区分用户输入路由和已确认发送

页面协调器提供语义上的 `insertText(text, operation?)`：草稿目标使用状态模块插入；直接目标调用原终端粘贴。返回值必须区分成功写入草稿、成功提交终端和失败，代码引用不能再仅凭一个布尔值就切换手机视图或宣称已发到终端。

显式草稿“发送”使用独立的终端提交入口，执行原 `paste()` 的就绪检查和 bracketed paste 处理，完整粘贴正文后再提交且仅提交一个 CR（`\r`）。CR 必须位于 bracketed paste 结束包装之后，不将 CR 拼入传给 paste 的正文；未启用包装时同样先正文、后一个 CR。此入口不经过 `insertText`，CR 不经过草稿路由或用户修饰键转换。普通 `paste()`、直接代码引用和上传路径保持不追加 Enter。粘贴失败立即结束，不发 CR；粘贴成功但 CR 提交失败时返回与整体失败不同的部分成功结果，提示正文已粘贴但 Enter 未发送，不自动重试任一步。失败及部分成功不修改草稿正文、选区或开启模式；只有正文与 CR 均被本地连接接受时才清空正文、选区归零并关闭模式及面板，不是远端执行确认。发送在同步本地提交期间防重入，不因重连、恢复前台或模式切换自动发送。手动关闭仍保留未发送草稿；显式清空需要独立确认，既有内存生命周期清理保持不变。

迁移范围包括原生文本粘贴、显式剪贴板读取、权限失败回退、代码引用、上传结果和软键栏普通字符。不得仅在若干按钮外包一层而遗漏 xterm 原生输入。

对于终端键盘输入，在用户输入事件层将焦点与编辑交给 textarea；终端 hook 禁止草稿模式下的用户控制键穿透，并保留协议应答和 resize 的原通路。不要在所有 `onData` 字节上尝试猜测文本与协议应答。实施时利用 xterm 的用户按键/输入事件层以及既有原生粘贴捕获点，验证首次按键、组合输入、设备查询三类来源。软键栏普通字符走文本路由，Enter/方向/删除作用于草稿编辑；无法映射的控制动作禁用并提示退出草稿模式。textarea 的复制、选取等原生快捷键保持正常。

### 4. 异步输入使用不可逆的草稿目标提升

每次剪贴板读取或上传开始时捕获 `{sessionId, entryIdentity, draftEpoch, startedInDraft}`。插入时若开始为草稿、当前为草稿或该条目的 epoch 已增加，则目的地为草稿；即使其后关闭模式也不降回直接目标。这样无需维护全局待输入队列，也覆盖等待期间开启再关闭的竞态。

所有结果先校验会话和生命周期身份。页面导航后不得调用新会话的输入回调；上传保持页面离开时取消，完成文件但路径未能插入时保留原真实路径提示，不自动重试。隐藏草稿被更新时只更新草稿存在标识，不重新开启模式。

直接上传的连接等待逻辑需要观察目标提升：等待期间开启草稿模式，应立即结束对终端就绪的依赖并把结果写入草稿，不能等到 30 秒超时才检查模式。用现有等待/取消机制扩展完成条件，不新增独立重试循环。草稿路径插入不调用 `terminal.focus()`。

### 5. 复用代码引用和文件上传语义

CodePanel/CodeDocumentView 接收输入目的地信息与统一插入回调，复用 `codeReference` 及文档状态检查。直接模式保持手机成功后返回终端；草稿模式不切视图，按钮及行内“＋”的可访问目标文案随模式改变。不存在额外“添加到草稿”按钮。

上传按钮、终端拖拽、终端粘贴和草稿框文件粘贴复用 `useUpload`；同一事件只能有一个处理者，含文件时保持文件优先，防止文本和文件路径重复进入。上传路径仍使用现有 shell 引号逻辑。失败不插入伪路径，多文件按原顺序处理并保留先前成功结果。后端限制及临时文件清理不变。

### 6. 兼容性与验证

自动化使用既有 Node/Vitest 浏览器/Playwright 分层，优先测试会影响用户的模式切换、选区插入、异步目标提升、会话隔离、失败保留和不意外输入。真实后端场景使用隔离 HOME/config/workdir，不连接开发服务。

通过真实 PTY 接收记录或可观察的 shell 行为确认“发送前没有用户输入、每次明确点击只粘贴一次完整正文、随后恰好一个 CR 且位于 bracketed paste 包装之外”，并验证仅两步均成功后清空正文及选区、关闭模式和面板，重新开启为空白，不能只检查回调被调用。启用与禁用 bracketed paste 的场景分别验证，不能把前者安全性推广到所有程序；覆盖粘贴失败无 CR、CR 失败的独立部分成功提示、失败保留正文和选区且模式开启、无重试，以及直接粘贴、引用、上传不追加 Enter。真实浏览器观察较小的 25% 初始高度及 160 px / 80% 边界、草稿开关紧邻代码按钮左侧、左列上下分割、手柄调高、宽度随左列变化、正常 PTY resize、手动关闭保留及成功关闭清空、终端实例与输出连续性、代码区全高且尺寸与操作不受影响、全屏、窄屏隐藏/返回及长文滚动。旧“无额外 Enter”和“成功保留正文及面板”证据仅属历史；原覆盖面板的“终端 host 尺寸不变”也不适用于当前合同。真机键盘、中文 IME 与系统文件选择器仍需手工检查；无法完成时如实记录环境限制，不以 Chromium 模拟冒充真机证据。

## Risks / Trade-offs

- 输入来源混合导致协议应答进入草稿 → 在用户事件层分流，并验证设备查询应答仍到达 PTY；不对所有底层数据作文本猜测。
- 终端失焦时丢失首字或中文组合 → 在焦点/指针入口引导 textarea，覆盖首字与 composition 行为，不自行逐字符拼装 IME。
- 上传等待中切换模式可能误发 → 会话绑定的 epoch 单调提升目标，等待条件同时观察模式变化。
- 草稿只保存在内存 → 使用文档明示刷新丢失，手动关闭模式不清空未发送草稿；无持久化安全承诺。
- 手机软键盘挤压页面 → 可视视口约束、独立正文滚动、固定可达操作区，不用模态层阻挡其他入口。
- 显式发送追加 CR，且多行正文可能被非 bracketed-paste 程序逐行执行 → 在使用文档说明提交与换行风险，不新增面板常驻帮助文字，不宣称任意应用安全；CR 提交失败明确报告部分成功，避免把正文误当作未发送而自动重试。
- 草稿模式阻止终端专用控制键 → 明确显示退出模式后操作的提示，避免 Ctrl+C 等控制字节混入待发送正文。
- 旧引用规格无条件直接发送 → 本次文档更新明确模式分支；归档同步时将旧合同限定到直接模式，不能覆盖新模式规则。

## Migration Plan

纯前端切换，不迁移持久数据或服务端 API。实施完成后更新 README.md、WebMux.md 的输入、引用、上传和手机使用说明，构建 web/dist 后再构建嵌入式二进制。默认关闭模式保留原工作流。回滚为上一前端构建即可；当前页面刷新会丢弃内存草稿，部署说明应提示先处理未发送内容。
