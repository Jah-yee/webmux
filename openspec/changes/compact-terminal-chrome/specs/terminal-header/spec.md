## Purpose

规定终端页顶栏在桌面与手机上的信息呈现和操作收纳，使会话标题与状态始终可辨识，低频操作仍可达，并为终端和代码内容保留尽可能多的可视空间。

## ADDED Requirements

### Requirement: 连接状态只在异常时显示文字

终端顶栏 SHALL 在会话标题旁显示会话状态点。连接正常时 SHALL NOT 显示“已连接”文字；连接处于重连中、已退出或会话不存在时，SHALL 在状态点旁显示对应文字，且文字不换行。状态点的可访问名称和提示 SHALL 同时包含会话状态与连接状态，使读屏软件在连接正常时仍能获知连接状态。该规则 SHALL 同时适用于桌面与手机。

#### Scenario: 连接正常

- **WHEN** 用户在 1440 px 或 393 px 视口打开已连接的运行中会话
- **THEN** 顶栏不显示“已连接”文字，状态点的可访问名称包含会话状态和“已连接”

#### Scenario: 连接中断后恢复

- **WHEN** 终端 WebSocket 断开并进入重连
- **THEN** 状态点旁显示单行“重连中”；重连成功后该文字消失

### Requirement: 窄屏顶栏只常驻高频操作

视口宽度小于 640 CSS px 时，终端顶栏 SHALL 只常驻：返回会话列表、会话标题、状态点（及异常连接文字）、快捷指令入口（按 `terminal-quick-commands` 规定仅在底部工具栏隐藏时出现）、草稿模式开关、终端/代码切换和终端菜单。全屏（按“全屏入口按平台能力提供”的规则）、上传文件和滚动到最新位置 SHALL 作为终端菜单中的菜单项提供，保持原有的禁用条件、可访问名称和行为（窄屏代码视图下滚动到最新位置仍切回终端）。会话标题 SHALL 占用常驻控件之外的全部剩余宽度，超长时省略。返回会话列表 SHALL 始终常驻，因为主屏幕 Web App 没有浏览器后退按钮。视口宽度至少 640 CSS px 时，顶栏 SHALL 保持现有按钮集合与顺序。

#### Scenario: 窄屏标题可辨识

- **WHEN** 在 320 px 和 393 px 宽视口打开名称为 `demo-agent` 的会话，终端视图和代码视图各查看一次
- **THEN** 顶栏单行、无横向溢出，393 px 下完整显示 `demo-agent`，320 px 下显示省略后的标题；顶栏不出现全屏、上传和滚动到最新位置按钮

#### Scenario: 从菜单上传文件

- **WHEN** 窄屏用户打开终端菜单并选择“上传文件”
- **THEN** 打开与原上传按钮相同的文件选择流程，上传进度、草稿模式下的路径写入和失败提示保持原有行为

#### Scenario: 宽屏布局不变

- **WHEN** 在 1440 px 桌面浏览器中打开终端
- **THEN** 顶栏仍直接显示全屏、上传文件、滚动到最新位置、快捷指令入口、草稿和代码切换按钮

#### Scenario: iOS 主屏幕 Web App 窄屏

- **WHEN** 在 iOS 27 iPhone 上从主屏幕 Web App 打开会话
- **THEN** 顶栏位于状态栏安全区下方，返回按钮可用，标题可辨识；终端菜单中的上传文件可打开系统文件选择器

### Requirement: 全屏入口按平台能力提供

浏览器提供可用的 Fullscreen API 时，系统 SHALL 按现有行为提供全屏与退出全屏入口（宽屏为顶栏按钮，窄屏为终端菜单项）。Fullscreen API 不可用时：在浏览器标签页中 SHALL 保留入口，点击后不尝试全屏，并提示可通过“添加到主屏幕”以独立模式打开；在主屏幕 Web App（`display-mode: standalone`）中 SHALL 不显示全屏入口。

#### Scenario: iPhone Safari 标签页

- **WHEN** iOS 27 iPhone 用户在 Safari 标签页中选择终端菜单的“全屏”
- **THEN** 页面不进入全屏也不报错，显示添加到主屏幕以独立模式打开的提示

#### Scenario: iPhone 主屏幕 Web App

- **WHEN** iOS 27 iPhone 用户在主屏幕 Web App 中打开终端菜单
- **THEN** 菜单中没有“全屏”项，其余菜单项正常显示

#### Scenario: iPad 支持全屏

- **WHEN** iPadOS 27 用户在 Safari 标签页中点击全屏
- **THEN** 页面进入全屏，再次点击可退出

### Requirement: 窄屏回到最新输出的浮动按钮

视口宽度小于 640 CSS px 且终端视图可见、终端不在恢复中时，若最新输出不在视野内，系统 SHALL 在终端区域右下角显示“回到最新”浮动按钮。“不在视野内”指终端视口不在缓冲底部；观察者（非控制方）平移比宿主更大的控制方网格时，宿主未滚动到底部也算。按钮 SHALL 带可见文字和可访问名称，不依赖悬停提示。点击后 SHALL 滚动到最新输出（观察者同时把宿主滚动到底部）并隐藏该按钮；回到底部（包括用户自行滚动到底）时 SHALL 自动隐藏。该按钮 SHALL 不遮挡软键栏或草稿面板，不取得终端焦点，不唤起也不收起软键盘。按钮 SHALL 始终位于可见视口与安全区内：软键盘弹出时随可见视口上移，主屏幕 Web App 中不被主屏幕指示条或横屏侧边安全区遮挡。

#### Scenario: 查看历史后回到最新

- **WHEN** 手机用户在有长输出的终端中向上滑动查看历史
- **THEN** 右下角出现“回到最新”按钮；点击后终端显示最新输出，按钮消失，软键盘状态不变

#### Scenario: 位于底部时不显示

- **WHEN** 终端视口处于缓冲底部，或新输出到达时终端自动保持在底部
- **THEN** 不显示“回到最新”按钮

#### Scenario: 观察者平移查看上方行

- **WHEN** 观察者在手机上查看比宿主更高的控制方网格，并向上平移离开最新行
- **THEN** 出现“回到最新”按钮；点击后宿主和终端视口都回到底部，按钮消失

#### Scenario: iOS 主屏幕 Web App 键盘弹出

- **WHEN** iOS 27 iPhone 主屏幕 Web App 中软键盘已弹出，用户向上滑动查看历史后点击“回到最新”
- **THEN** 按钮显示在键盘上方的可见区域内；点击后终端回到最新输出，软键盘保持弹出
