# 使用指南

## 会话列表

首页按「仓库 → 工作树 → 会话」分组：

- 仓库按登记顺序排列，可折叠；工作树按路径排列，组内会话按创建时间倒序排列。
- 每个仓库只在首页显示“已添加到主页”的工作树：默认只有主工作区，通过页面新建的 worktree 自动添加。点仓库旁的「添加已有 worktree」可搜索并多选其余工作树；工作树菜单中的「从主页移除」只是不再显示，不会删除工作树。有会话的工作树始终显示，未添加的会标注「未添加到主页」。这项选择保存在当前浏览器中，不在设备间同步。
- 未关联已登记仓库的会话显示在「直接会话」中；工作树已失效的会话保留在「已不可用工作区」。
- 每个会话行显示标题、状态、最近活跃时间、连接设备数和终端屏幕预览，并按状态着色背景。
- 启用可选 shell 集成后，会话行还会显示「Shell 报告目录」：程序通过 OSC 7 报告的当前目录。它只是导航线索，不改变会话按启动目录或仓库工作树的归属；远端主机报告的目录会标注「远端」，不会用于本机文件定位。会话菜单可复制该目录（没有报告时复制启动目录）。
- 列表通过 WebSocket 实时更新；Git 状态在打开页面、切回前台、重连、手动刷新和操作完成后重新读取。

会话标题优先使用创建时填写的名称，其次是程序通过 OSC 0/2 设置的终端标题，最后是工作目录名。

### 可选的 Shell 目录报告

WebMux 接受 [OSC 7](https://wezterm.org/escape-sequences.html) 的 `file://主机/绝对路径` 报告，不会自动改写 shell 配置。需要时自行把下面片段加入 bash 或 zsh；不启用时终端和会话列表照常工作。

```bash
# bash
_webmux_osc7() {
  local p=${PWD//'%'/'%25'}
  p=${p// /%20}
  p=${p//'#'/'%23'}
  p=${p//'?'/'%3F'}
  printf '\033]7;file://%s%s\007' "${HOST:-${HOSTNAME:-localhost}}" "$p"
}
PROMPT_COMMAND="_webmux_osc7${PROMPT_COMMAND:+;$PROMPT_COMMAND}"
```

```zsh
# zsh
autoload -Uz add-zsh-hook
_webmux_osc7() {
  local p=${PWD//'%'/'%25'}
  p=${p// /%20}
  p=${p//'#'/'%23'}
  p=${p//'?'/'%3F'}
  printf '\033]7;file://%s%s\007' "${HOST:-${HOSTNAME:-localhost}}" "$p"
}
add-zsh-hook precmd _webmux_osc7
```

只报告目录，不采集命令正文。SSH 等子会话可能报告另一台机器的路径，WebMux 按主机名区分本机与远端；远端目录仅用于展示和复制，不参与本机文件定位。进程退出后报告即清除。

### 会话状态

| 状态       | 含义                                                                  |
| ---------- | --------------------------------------------------------------------- |
| 运行中     | 最近 2 秒内有输出，或已无输出但没有提示符、终端读取或关注信号         |
| 可能在等你 | 末行像提示符 / 确认问题，或进程在等待终端输入；`sleep` 等计时休眠不算 |
| 空闲       | 超过 `idle_after_seconds` 无输出，且没有上述等待特征                  |
| 已退出     | 进程已结束，显示退出码（信号退出记为 `128 + signal`）                 |

状态只用于展示，不触发任何自动动作。

### 需要你介入的提醒

程序主动发出的终端信号优先于上述启发式：一旦收到，会话显示具体提醒并保持“等待”，即使 agent 仍在刷新 spinner、计时器或状态栏。

| 提醒     | 来源                                                         |
| -------- | ------------------------------------------------------------ |
| 需要回答 | agent 结构化事件 `question_asked`                            |
| 等待授权 | agent 结构化事件 `permission_request`                        |
| 已完成   | agent 结构化事件 `stop` / `idle_prompt`                      |
| 出错停止 | agent 结构化事件 `stop_failure`                              |
| 有通知   | 桌面通知序列 `OSC 9` / `OSC 777;notify`                      |
| 响铃提醒 | 终端响铃（BEL），在你最后一次输入 1 秒后才计入，避开补全响铃 |

结构化事件使用 Warp 的 `OSC 777;notify;warp://cli-agent;{json}` 格式，webmux 只读取其中的事件名，不保存提问、回答等正文。提醒在你向该会话输入（终端自动应答除外）、agent 报告重新开始工作或进程退出时清除；输出和浏览器断线重连都不会清除它。

**omp**：无需配置。webmux 默认在会话环境中设置 `WARP_CLI_AGENT_PROTOCOL_VERSION=1`，omp 据此发出结构化事件；关闭 `agent_protocol` 后 omp 改用响铃报告提问和完成。

**Claude Code**（2.1.141 及以上）：在 `~/.claude/settings.json` 中注册 hook，由 Claude Code 代为输出事件序列：

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "permission_prompt|idle_prompt|agent_needs_input|elicitation_dialog",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/webmux-attention.sh"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/webmux-attention.sh"
          }
        ]
      }
    ]
  }
}
```

```bash
#!/bin/bash
# ~/.claude/hooks/webmux-attention.sh — silent outside webmux sessions; needs jq.
[ -n "$WEBMUX_SESSION_ID" ] || exit 0
input=$(cat)
case "$(jq -r '.hook_event_name' <<<"$input")" in
  Notification)
    case "$(jq -r '.notification_type // empty' <<<"$input")" in
      permission_prompt) event=permission_request ;;
      agent_needs_input | elicitation_dialog) event=question_asked ;;
      idle_prompt) event=idle_prompt ;;
      *) exit 0 ;;
    esac
    ;;
  Stop) event=stop ;;
  *) exit 0 ;;
esac
seq=$(printf '\033]777;notify;warp://cli-agent;{"v":1,"agent":"claude","event":"%s"}\007' "$event")
jq -nc --arg seq "$seq" '{terminalSequence: $seq}'
```

**Codex CLI**：在 `~/.codex/config.toml` 的 `[tui]` 中设置 `notifications = true`，Codex 在回合结束和请求授权时发出 `OSC 9` 或响铃，webmux 分别显示“有通知”或“响铃提醒”。

其他程序只要输出上述任一序列即可获得提醒，不需要 webmux 适配。

### 预览设置

首页“设置”可调整预览显示的行数（1–50，默认 10）和跳过末尾的行数（0–50，默认 1）。设置保存在当前浏览器的 localStorage 中，不影响其他设备。

会话卡片始终为预览保留设定行数的高度，暂无输出时也不收起。列表按创建时间排列，后台输出和状态更新不会重新排序或挤动其他会话。

## 新建会话

“新建会话”提供三种启动位置：

- **直接目录**：任意目录，支持路径补全（↑↓ 选择，Enter / Tab 进入，Alt+↑ 返回上级），目录不存在时可确认创建。
- **已有工作树**：在已登记仓库的某个工作树（或其子目录）中启动。
- **新工作树**：先创建 Git worktree，再启动会话。

启动方式分为两组：

- **内置预设**：来自配置文件 `[[presets]]`（默认 Shell、Claude Code、Codex CLI、omp），允许时可追加参数。修改预设需编辑配置文件并重启服务。
- **我的启动配置**：在设置页“启动配置”中保存的“名称 + 完整命令 + 环境变量”，保存在服务端，换浏览器或设备后仍可使用。可从内置预设填入命令后另存；保存的是当时的命令副本，之后修改预设不会改变它。环境变量值默认遮挡，列表和新建会话页只显示变量个数。

一次性命令可展开“临时命令（不保存）”输入，不会写入服务端。新建会话页在当前浏览器记住上次的选择。命令按 argv 直接执行，**不经 shell 展开**；需要管道、变量等 shell 语法时，请显式写成 `bash -lc 'npm run dev | tee dev.log'`。Claude Code、Codex CLI 与 omp 预设经交互式 bash 启动，以加载 `~/.bashrc` 中的环境变量；追加参数会原样传给 agent。

启动配置存储不可用（文件损坏或同一状态目录有另一实例）时，设置页显示原因与文件路径，内置预设与临时命令照常可用。

预设不会自动安装 agent，对应程序必须能被服务找到；agent 预设经交互式 bash 启动，因此也可由 `~/.bashrc` 中的 `PATH` 补充。

## 从终端启动与附着

在服务所在机器（含 WSL 内）的 shell 中，`webmux` 经本机套接字访问服务，无需 Token：

```sh
webmux run -- claude --resume          # 在当前目录创建会话并立即附着
webmux run --detach --name review -- codex   # 只创建，输出 "<ID>\t<本机链接>"
webmux run --env VIRTUAL_ENV=/w/.venv --env PATH=/w/.venv/bin:/usr/bin -- python app.py
webmux ls [--json]                     # 列出会话；--json 为服务端原始数组
webmux attach <ID> [--observe]         # 附着；Ctrl+] 分离，会话继续运行
webmux open <ID> [--browser]           # 输出（并打开）不含 Token 的会话链接
```

- `--` 之后的参数原样作为 argv，不经 shell 展开；`--cwd` 指定启动目录（默认当前目录，`~` 由服务端展开）。
- 会话环境来自**服务进程**，不是调用方 shell：`--env NAME=VALUE` 只追加显式列出的变量，不复制当前环境。
- 附着时终端切换为原始模式，默认取得控制权并同步窗口尺寸；`--observe` 只观察。会话退出时以其退出码结束；分离以 0 结束；服务未运行以 3 结束，不会自动启动服务。附着开始时以终端复位后的完整回放呈现会话内容。
- 浏览器等其他客户端接管后，原生终端左上角显示 `Controlled by <客户端> · Enter to take control · Ctrl+] to detach`，期间的按键（包括终端对焦点、设备、颜色查询的自动应答）一律丢弃，不会抢回控制；按 Enter 重新接管（该 Enter 不发送给会话），随后按本终端尺寸重绘。程序开启 modifyOtherKeys、kitty 键盘协议或 Windows Terminal 的 win32-input-mode 后，Enter 与 `Ctrl+]` 的编码形式同样识别；附着结束时关闭这些键盘、鼠标、焦点与粘贴上报模式，避免外层 shell 收到无法解析的按键编码。
- 默认附着的 `run` 在接管终端前，向标准错误输出 `webmux: session <ID> · <本机链接> · Ctrl+] to detach`，便于把链接带到手机上；标准输出只属于会话。需要附着时标准输入输出必须是终端，否则以退出码 2 结束且不创建会话。
- 典型流程：在原生终端 `webmux run -- claude` → `Ctrl+]` 分离 → 手机打开链接、输入即接管 → 回来后 `webmux attach <ID>` 接续，全程是同一个进程。

## 在 Windows 终端中使用

`webmux-windows-<arch>.exe`（建议放入 `PATH` 并重命名为 `webmux.exe`）在 PowerShell / Windows Terminal 中提供 `run`、`attach`、`ls`、`open`、`status` 与 `version`，会话运行在 WSL 中的 WebMux 里。每条连接都会启动 `wsl.exe --exec webmux bridge` 访问本机 API，因此不需要 Token，也不依赖 WSL 的 localhost 转发或网络模式；服务需已在 WSL 中运行（托盘或 `webmux serve`）。

- **发行版**：`--distro`、环境变量 `WEBMUX_DISTRO`、托盘设置 `%APPDATA%\WebMux\tray.json`、WSL 默认发行版，依次生效。WSL 内 `webmux` 路径同理：`--webmux`、`WEBMUX_WSL_PATH`、托盘设置、`~/.local/bin/webmux`。
- **目录换算**：未指定 `--cwd` 时把当前目录换算为 WSL 路径：盘符路径按发行版的自动挂载规则（`wslpath`，默认 `C:\work` → `/mnt/c/work`）；`\\wsl.localhost\<发行版>\…` 或 `\\wsl$\<发行版>\…` 换算为对应 Linux 路径；网络共享、其他发行版与设备路径无法换算，以退出码 2 结束，请用 `--cwd /linux/path` 指定。
- **控制台**：附着时控制台进入 VT 原始模式并使用 UTF-8 代码页，`Ctrl+C` 发送给会话，`Ctrl+]` 分离；窗口尺寸每 250 毫秒同步一次；退出时恢复原模式与代码页。需要 Windows 10 22H2 及以上，推荐 Windows Terminal。
- **引号**：PowerShell 在把参数交给原生程序前会再处理一次引号。需要字面传递 `$`、`;` 等字符时用单引号（`webmux run -- printf '%s;$(id)' 'a b'`），或在 `--` 前使用 `--%` 停止解析。

## 终端

- 进入终端时先回放服务端缓冲，再续接实时输出；断线后以指数退避（0.5–8 秒）自动重连，回到前台时立即重新附着。若本页终端仍在且服务端还保留断线后的输出，只补发缺失部分，不清屏；否则清屏全量回放。缓冲已覆盖最早输出时，菜单“复制全部缓冲”会注明。
- 同一会话可在多个设备（浏览器标签页）上同时打开，任一端的输入其他端可见。**只有控制端决定 PTY 尺寸**：首个打开的设备成为控制端，之后的设备先观察，顶部显示“观察中 · 某设备控制输入与尺寸”。观察端按控制端的行列显示，超出屏幕时可拖动平移；键盘开合、窗口变化或重连都不会改变 PTY 尺寸。在观察端输入、发送草稿、点 `⌨` 或“接管控制”即取得控制权；控制端离开后控制权空缺，直到下一次输入。终端设备查询只由控制端（无控制端时为最早连接）回答。
- 顶栏提供返回、草稿模式、代码工作区、全屏、上传和“滚动到最新位置”按钮；菜单中可复制全部缓冲、清屏、重新同步、调整字体和关闭会话。连接正常时顶栏不显示文字（状态点的提示包含“已连接”），重连中、已退出或会话不存在时在状态点旁显示。
- 窗口窄于 640px（手机竖屏）时，顶栏只保留返回、标题、状态、快捷指令入口、草稿、终端 / 代码切换和菜单；全屏、上传文件和滚动到最新位置移到菜单顶部。向上翻看历史时，终端右下角出现“回到最新”按钮。
- 已退出的会话保留退出码和最后输出，直到手动移除。
- 关闭会话先发送 SIGHUP，5 秒后仍未退出则发送 SIGKILL，并清理整个进程树。

### 复制与粘贴

- 桌面使用 Ctrl+Shift+C / Ctrl+Shift+V。
- 粘贴遵循程序启用的 bracketed paste 模式，Bash、Claude Code 等程序中多行文本不会被逐行提交。
- 终端程序通过 OSC 52 发出的复制请求会写入浏览器剪贴板；重连回放历史时不会重复触发。
- HTTP 环境下 Clipboard API 不可用时，自动回退为可手动粘贴 / 复制的文本框。

### 文件上传

点击“上传文件”、把文件拖入终端，或粘贴剪贴板中的文件 / 图片。上传完成后，带 shell 引号的服务器绝对路径会插入终端（不回车）。

- 文件保存在服务器临时目录下独立的 `webmux-upload-*` 子目录中（遵循 `TMPDIR`），权限 0700 / 0600，不写入工作区。
- 单文件上限 100 MiB，上传期限 5 分钟，可随时取消。
- 上传成功的文件不会随会话关闭自动删除，由用户或系统临时目录策略清理。

## 草稿模式

点击顶栏“草稿”打开草稿面板：终端下方出现可调整高度的多行输入框。开启后，键盘输入、粘贴、软键栏字符、代码引用和上传路径都进入草稿，而不是直接发送给终端。

- 点击“发送”才提交：完整正文与一次 Enter 作为一个整体写入终端，其他设备的输入不会插在中间。输入框内 Enter 只换行。
- 发送后状态行依次显示“已发出”“服务端已收到”，**已写入终端**后清空草稿并关闭面板。“已写入终端”只表示字节进入了终端，不代表 agent 已接受或执行成功。
- 确认前正文锁定。连接中断时显示“结果未知”，重连后自动查询；也可“按原提交重发”（服务端已收到时不会重复写入）或“转为草稿”。未写入或服务端无记录时恢复为可编辑草稿并提示原因，不会自动重发。
- 手动关闭草稿模式只隐藏面板，未发送内容会保留。
- 草稿操作行的“暂存”可为同一会话保留多条待办文本：新增、编辑、上移、下移、删除，或取用到当前草稿。取用只改变草稿，不会自动发送，也不会自动聚焦终端。
- 当前草稿非空时，取用可以选择追加到正文之后，或替换正文；替换前会把原正文保留为一条新的暂存。存在未确认提交时不能转存或取用，暂存仍可查看、编辑和删除。
- 草稿按会话隔离并保存在当前浏览器：刷新、关闭页面、系统回收标签页或认证失效后重新打开会话，草稿面板会恢复当前正文和目标会话，顶栏按钮会显示暂存条数；仍需点击发送。7 天未修改或会话已不存在时自动清理；可在设置页关闭本机保存或清除全部草稿和暂存。
- 关闭草稿面板后，顶栏“草稿”按钮会显示暂存条数；终端菜单中的“暂存”可在不开启草稿面板时查看和整理暂存。暂存新增或修改时会提示“暂存已更新”，但不会自动打开草稿面板。
- 每会话最多保留 20 条暂存，单条最多 20,000 字符，合计最多 100,000 字符；超出限制时新增或编辑会被拒绝并说明原因。
- 本机存储关闭或写入失败时，暂存只保留在当前页面并提示刷新后可能丢失；损坏、过期或所属会话已不存在的暂存会被清理。
- Ctrl+C 等终端控制键需先退出草稿模式。

> [!CAUTION]
> 如果目标程序未启用 bracketed paste，草稿正文中的换行也可能被当作提交。

## 代码工作区

点击顶栏“代码”在终端旁打开只读代码工作区。宽屏（≥1024px）并排显示，窄屏在“终端 / 代码”之间切换；终端始终保持同一个 PTY 并持续接收输出。导航开关、文件标签、“刷新全部”和独立窗口按钮在同一行；代码根目录显示在导航面板顶部。窗口窄于 640px 时，文档路径、“查看 Diff / 返回文件”、“完整文件”、SVG 预览 / 源码和图片预览来源收进标签行右侧的“代码菜单”；内容更新、快照过期等提示仍直接显示。

- **文件**：逐层浏览或按路径搜索；Git 忽略的未跟踪文件默认隐藏。
- **修改**：按未暂存、已暂存、未跟踪分组列出 Git 修改。Diff 随阅读宽度自动切换并排或统一布局，固定显示行号，可查找、换行和展开上下文；Ctrl/⌘+Alt+G 跳转行。“完整文件”菜单可打开修改前或修改后的快照。
- **阅读**：只读 CodeMirror 编辑器，带语法高亮、文件内查找和跳转行，最多同时打开 20 个标签。
- **图片**：PNG、JPEG、GIF、WebP、AVIF、BMP、ICO 直接在面板中预览，可适应窗口、1:1、放大 / 缩小，鼠标或单指拖动，手机上双指缩放；显示格式、像素尺寸与文件大小。动作栏“下载”按原文件名保存与源文件一致的字节。按扩展名加文件头识别：改名为 `.bin` 的图片仍按二进制处理，扩展名与内容不符时以内容为准。SVG 默认预览、可切换到源码阅读和按行引用；预览不执行脚本、不加载外部资源。图片修改的 Diff 显示新增 / 删除 / 修改与大小变化，可切换旧侧和新侧预览。
- **按路径打开**：在文件导航展开「按路径打开」，输入相对路径时以 Shell 报告目录为基点（没有报告时用启动目录），绝对路径也可用；服务端按实际文件系统解析符号链接后，只有位于当前代码根内才会打开，目录则跳转到文件树。Shell 报告远端目录时不能用于本机定位。
- **引用**：选中行（桌面点击行号、Shift 点击选范围；手机点击行后点“＋”）后发送到终端，格式如 `/repo/main.go:12-18`。开启草稿模式时引用会加入草稿。文字 Diff 根据点击的行自动确定版本，无需选择引用来源；未选行时发送文件路径，选行后可点“引用整个文件”恢复。选择方式提示显示在底部操作栏左侧，手机上省略。
- **独立窗口**：桌面浏览器在工作区顶栏“刷新全部”右侧显示弹出按钮，把整个代码工作区移到单独的窗口中，原位置显示占位提示。已打开的标签、引用和变化检测照常工作，收起主窗口里的代码栏也不影响独立窗口；关闭窗口或点“收回”后回到原位，刷新或离开主页面时窗口随之关闭。Chrome / Edge 在 HTTPS 或 localhost 下使用置顶的画中画窗口；其他情况（HTTP 访问、Safari、Firefox）使用普通弹出窗口，被浏览器拦截时需允许本站弹窗。手机、平板、窄于 640px 的窗口，以及带触摸屏设备上“添加到主屏幕”的 Web App 不显示这个按钮；macOS Safari 的 Web App 仍可使用。

工作区根目录绑定到会话启动目录所在的 Git worktree（无 Git 时为启动目录本身），不会跟随终端中的 `cd`。代码可见时每 5 秒检测文件变化，只提示不自动替换内容，点击刷新后才加载新版本。

工作区从不修改文件、Git 索引或配置。读取有大小限制：单个文本文件最多 2 MiB / 20000 行，图片预览最多 20 MiB，下载最多 100 MiB，单个目录最多检查 10000 项。

## 仓库与 worktree

需要系统安装 Git；没有 Git 时终端功能不受影响。

- **添加仓库**只登记已有仓库，不会 clone 或 init。登记信息在服务重启后保留。
- **新建 worktree** 可基于指定的本地基线创建新分支，或检出未被占用的已有本地分支。默认路径为仓库旁的 `<仓库名>.worktrees/<分支名>`，不会自动 fetch、复制 `.env` 或安装依赖。
- 同一工作树可启动多个会话，它们**共享同一份文件**。
- **关闭会话**不会删除工作树；**从列表移除仓库**只移除登记，不删除目录或分支。
- **删除 worktree** 先预览，默认拒绝存在未提交修改、未跟踪 / 忽略文件或活动会话的工作树。主工作区、bare、locked 及含子模块的工作树不能通过页面删除。

> [!WARNING]
> 强制删除需输入完整路径并授权关闭相关会话，会永久丢弃目录中的全部内容（包括 `.env` 和未提交修改）。分支会保留。

添加的仓库必须可信：Git 会按仓库配置执行 hooks 和 filters。

## 移动端

- 软键栏在带触摸屏的设备（手机、平板，包括连接手写笔或键盘时）上默认显示，提供 `⌨`（唤起 / 收起键盘）、粘贴、`/`、`@`、Esc、Tab、Ctrl、Alt、方向键、Home/End、PgUp/PgDn 以及 Ctrl+C/D/Z/L/R。Ctrl / Alt 为一次性修饰键。
- 在触摸屏设备上，只有点击 `⌨` 才会唤起虚拟键盘：进入终端、轻点或用手写笔点击终端、开启草稿、关闭弹窗、上传完成都不会自动聚焦输入。键盘已弹出时，方向键、Esc、Tab 等发送软键保持焦点、不收起键盘；快捷指令菜单和粘贴弹窗会把焦点转入弹层。
- 单指滑动滚动历史（全屏 TUI 中转换为滚轮事件），双指捏合调整字体（12–20px）。
- 长按约 0.5 秒选中词语，继续拖动可跨行扩选，然后点击“复制选中”。
- 支持浏览器原生全屏，也可“添加到主屏幕”以独立模式运行。iPhone 不支持网页全屏：Safari 标签页中的“全屏”会提示添加到主屏幕，主屏幕 Web App 中不显示该入口。
- 窄屏触摸设备上，图片工具栏只保留“适应窗口”和“1:1”，用双指缩放图片。
- 终端输入关闭了自动大写、拼写检查和自动纠正。

Chromium 移动模拟不能完全代替真机。iOS Safari / Android 的输入法、系统键盘和锁屏恢复行为请以真机为准。
