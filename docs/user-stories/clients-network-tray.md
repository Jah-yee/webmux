# 原生客户端、隧道与托盘

## M. 原生终端、CLI 与本机控制面

| 编号 / 功能                 | User story                                                                                                            | 验收要点                                                                                                                                                                                                                                                                         |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-M01 从本地终端启动       | 作为终端使用者，我希望用 `webmux run -- COMMAND ARG...` 创建并附着会话，以便保留原来的 CLI 工作习惯并随时转到浏览器。 | `--` 后 argv 原样传递；默认当前目录，可指定名称与目录；`--detach` 只创建并输出 ID 和无 token 本机链接；默认附着前向 stderr 公告会话入口，stdout 保留给会话；非 TTY 的附着请求在创建前拒绝。                                                                                      |

| US-M03 附着与观察           | 作为使用者，我希望 `webmux attach ID` 回到已有 PTY，或只观察，以便在手机和原生终端间接续同一任务。                    | 初次附着完整回放并进入原始终端模式；默认取得控制并同步尺寸，`--observe` 不输入或改尺寸；程序已开启明暗报告（DEC 2031）时，取得控制后按本地终端背景色（OSC 11）报告明暗，使程序改用本地终端配色；会话退出时返回其退出码；服务未运行返回 3，不自动拉起服务；结束后恢复控制台状态。 |
| US-M04 分离与重新接管       | 作为原生终端使用者，我希望浏览器接管后本地按键不会误抢控制，并可明确接管或分离，以便安全切换设备。                    | 被接管后显示控制提示，丢弃普通键及终端自动应答；Enter 仅接管、不发给会话；Ctrl+] 分离且进程继续运行，返回 0；兼容 modifyOtherKeys、kitty 与 Windows 编码按键，退出时关闭临时上报模式。                                                                                           |
| US-M05 命令行发现与打开会话 | 作为使用者，我希望用 `ls` 列出会话并用 `open ID` 获取入口，以便不经过首页就能找到目标。                               | `ls` 显示 ID、名称、状态、命令和目录，`--json` 输出原始会话数组；`open` 校验目标并打印不含 token 的本机链接，`--browser` 可打开默认浏览器。                                                                                                                                      |
| US-M06 诊断运行实例         | 作为部署者，我希望用 `status` 看到健康状态、访问地址和配置漂移，以便确认正在使用哪个实例。                            | 优先本机 API，必要时使用运行时记录与 TCP 健康检查；区分运行、未运行、无响应或错误并给出退出码；`--json` 提供版本化结果，只有同时 `--reveal-token` 才揭示 token；提示 listen/token 配置与运行实例的差异。                                                                         |
| US-M07 停止指定实例         | 作为部署者，我希望可靠地停止自己启动的服务，以便清理后台运行实例。                                                    | `stop` 优先经本机控制面关闭，必要时验证运行记录后退回 SIGTERM 和超时 SIGKILL；无记录不随意发信号；systemd/launchd 实例默认要求使用服务管理命令，显式 `--force` 可覆盖；支持超时与 JSON 结果。                                                                                    |
| US-M08 本机桥接与权限边界   | 作为本机使用者，我希望 CLI 和 Windows 桥接无需维护网络 token，以便直接访问当前用户的服务。                            | Unix 套接字验证同用户身份，`bridge` 在标准输入输出间传输；浏览器网络入口仍要求认证；会话内进程不能用本机管理 API 读取 token、停止服务或控制隧道，也不能经套接字读取或修改 `/api/tunnel` 及其子路径（403）；套接字不是不同账号间的共享授权机制。                                  |

## N. Cloudflare 公网隧道

| 编号 / 功能             | User story                                                                                                         | 验收要点                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-N01 临时公网入口     | 作为明确选择公网访问的部署者，我希望启用 Quick Tunnel，以便临时从无法接入 VPN 的设备连接自己的终端。               | 可在 Web 设置页保存 Quick 模式并确认启用，也可用 `--tunnel` 或 `[tunnel].enabled`；无需 Cloudflare 账号，获得随机 HTTPS 地址，不承诺固定地址或 SLA；未启用时不创建隧道。Web 设置在服务器 `<state_dir>/tunnel.json` 原子保存（目录 0700、文件 0600、独占锁），跨浏览器与重启生效并优先于 TOML 的模式、主机名、凭据及开关；显式 `--tunnel` 只覆盖当前进程开关，不改写磁盘。                                                                                                             |
| US-N02 固定域名隧道     | 作为已有 Cloudflare 配置的部署者，我希望使用 Named Tunnel，以便通过预设的公共主机名访问。                          | Web 页可保存 Named 模式、裸主机名及写入式隧道 token，并在 Cloudflare 配置回源；也支持 TOML 配置。省略 token 保留已有凭据，首次配置或显式空凭据不可保存 Named；切回 Quick 清除主机名与凭据；凭据不回显、不放入 URL 或浏览器持久存储，只显示是否已配置，经环境变量而非命令行传给 cloudflared；指定空配置避免本机其他 cloudflared 配置干扰。                                                                                                                                             |
| US-N03 隧道认证与扫码   | 作为部署者，我希望公网入口始终要求足够强的 token，并能扫码连接，以便明确控制入口凭据。                             | WebMux 登录 token 与 Cloudflare 隧道 token 不同；首次启动可生成并持久化 256 位随机登录 token，已有配置缺少登录 token 时生成本次进程的随机值；运行中启用要求当前登录 token 至少 43 字符，不生成或更换登录 token，条件不足提示修复后重启；显式 CLI/TOML 隧道启动仍校验登录 token。传统启动路径可输出含 token 链接与二维码，运行时启动只打印无 token 公网地址；持久化 token 重启保留，仅临时 token 重启更换，含 token 链接和二维码本身即授权入口，可能被启动日志保留。                   |
| US-N04 获取 cloudflared | 作为部署者，我希望自动定位或下载匹配的 cloudflared，以便不用手工管理隧道依赖。                                     | 按显式路径、PATH、状态缓存定位，不存在时下载固定版本；支持有序下载镜像，空镜像列表禁用回退；各来源均校验内置 SHA-256 后执行；定位或校验错误明确报出；路径和下载镜像等运维项仍由 TOML 管理，不由 Web 设置覆盖。                                                                                                                                                                                                                                                                        |
| US-N05 隧道故障隔离     | 作为使用者，我希望隧道断开时本机会话仍继续，以便恢复远程入口后继续任务。                                           | 隧道退出立即撤销对应公网来源授权，本地访问和 PTY 保留，不自动重试；Web 保存的启用状态在启动时遇到短登录 token、依赖下载或进程启动失败，只把隧道置为 failed，HTTP/本机 API 继续可用；设置文件损坏、不可读或锁冲突时保持原文件并禁止公网启动，不回退到 TOML/CLI 开启；关闭操作即使落盘失败也立即停止当前进程的隧道并撤销授权，返回 503 与 `notPersisted: true`，明确提醒修复存储后再重启，不能声称下次仍关闭；正常退出关闭隧道而不改持久开关。                                          |
| US-N06 在线切换隧道     | 作为浏览器或托盘使用者，我希望服务运行中开启或关闭公网隧道，以便控制入口而不中断会话。                             | Web 页与本机控制面共用持久化开关，启用前确认，要求已有至少 43 字符登录 token；成功保存后异步应用，无需重启，重复启用不产生第二个 cloudflared；更换已启用的模式、主机名或凭据先撤销旧授权并停止旧进程，再启动新配置，迟到事件不能恢复旧入口；普通保存/启用落盘失败不应用新设置，关闭例外见 US-N05。托盘仅在 `settingsAvailable: true` 时提供 Web 设置入口；勾选以可选 `enabled` 表示的当前进程期望（含 CLI 覆盖）为准，不等于磁盘开关或 ready，旧服务缺该字段时回退到 starting/ready。 |
| US-N07 配置说明与指南   | 作为不熟悉 Cloudflare 的使用者，我希望在设置页和文档中按步骤完成 Named Tunnel 配置，以便独立获得固定域名入口。     | 设置入口打开 `/settings/tunnel`，区分 Quick/Named，显示配置来源、凭据是否已配置、启用前提与存储问题；保存与启用分开，提供 Named 配置步骤、文档链接和写入式凭据框，不读取真实凭据；恢复配置文件默认值前确认，成功后删除 Web 覆盖并停止当前隧道，不立即按 TOML 自动开启，下次启动才遵循 TOML；恢复失败不假装成功；文档覆盖 Windows/WSL、验证、排错与安全。                                                                                                                              |
| US-N08 查看隧道运行状态 | 作为部署者，我希望在设置页看到当前公网隧道的运行状态、模式与主机名，以便确认隧道是否启用时不必查看托盘或服务日志。 | 独立显示当前进程期望 `enabled` 与 off/starting/ready/failed，启动失败仍可保留启用期望，不能把它当成可用公网入口；状态轮询反映托盘和其他设备变化，ready 才显示无 token 公网地址；只读 `/api/config` 的旧 `tunnel.enabled` 仍仅表示 starting/ready，模式和主机名动态跟随有效设置，推送资格使用当前 Named 主机名；GET 设置即使存储损坏仍可读状态及错误，不能启用时给出原因；接口不返回 Cloudflare 凭据，桌面和移动布局无横向溢出。                                                       |

| US-O04 登录启动与单实例            | 作为 Windows 使用者，我希望登录后出现一个托盘实例，以便随时找到服务入口。                                                              | 同一 Windows 用户只运行一个托盘，再次启动通知已有实例；可选择注册当前 exe 为登录启动；exe 移动后需重新登记；无需以管理员启动托盘。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

| US-O11 判断 WSL 服务兼容与版本对应 | 作为 Windows 使用者，我希望托盘告诉我它与 WSL 中的 webmux 是否兼容、版本是否对应、该更新哪一边，以便两边分别升级后不再遇到含糊的失败。 | 托盘启动后首次取得状态、切换发行版或修改 `webmux` 路径、安装完成后，以及处于缺失或不兼容状态时打开菜单，在后台以 `version --json` 检查（旧版本回退文本并视为契约 v1），单次不超过 30 秒，日志记录两侧版本与契约；兼容只看控制契约，对应只比较版本号，`dev` 等非发布版本无法判断且不提示；结果只出现在菜单状态行，不发通知或弹窗：较旧一方、“比托盘新，请升级托盘”或“版本过旧，请升级”；WSL 较新且为发布版本时提供“下载托盘 <版本>”打开 Release 页面；契约不兼容仍可启动、停止、重启，以 Windows 侧可达性判断运行并显示“运行中（不兼容，功能受限）”，状态无法解析不判失败、不自动重启；缺少本机 API 时禁用启动；运行实例与已安装文件版本不同时提示重启后生效，只有托盘管理的实例可从菜单重启。 |

隧道设置的增量兼容同样归入 US-O11：不得从版本号或存在 `tunnel` 字段推断设置页可用，只有 `settingsAvailable: true` 才显示入口；缺少该字段的旧服务仍保留原有隧道控制。可选 `enabled` 表示当前进程期望（包括 `--tunnel` 覆盖），不是持久磁盘值；缺失时才按 starting/ready 推断开关。

Windows 原生终端客户端复用 US-M01–US-M06：提供 run、attach、ls、open、status 与 version，服务仍在 WSL 中。发行版与 webmux 路径按命令行、环境变量、托盘设置、默认值依次解析；用 `wslpath` 换算盘符路径，识别同发行版的 WSL UNC 路径，无法换算时要求显式 Linux `--cwd`。经 `wsl.exe --exec webmux bridge` 连接，不依赖 localhost 转发；附着时使用 UTF-8/VT 控制台，恢复后还原模式与代码页。
