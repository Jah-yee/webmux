## 阅读约定与产品边界

- **使用者**：通过桌面、手机或平板浏览器使用服务器上的 Shell、CLI agent 和其他终端程序的人。
- **部署者**：安装、配置和维护自己的 WebMux 服务的人，通常也是使用者。
- **贡献者**：开发、测试和发布 WebMux 的人；相关故事单独列在 L 节。
- WebMux 面向单用户，多设备连接仍共享同一服务用户的权限，不存在团队账号、成员角色或设备间文件隔离。
- **会话**是服务端持有的 PTY 与进程；**工作树**是磁盘上的 Git worktree。浏览器断开不会结束会话，关闭会话不会删除工作树。
- 会话、终端缓冲和发送确认记录不是跨服务重启的持久数据；仓库清单持久保存在服务端，草稿、暂存和显示偏好保存在当前浏览器。
- 本文不承诺进程沙箱、公网访问安全、文件编辑、自动 clone/fetch、自动安装 agent 或跨服务重启恢复终端。
- 故事编号保持稳定。新增功能应补充故事；改变行为时同步修改验收要点与相关测试，不因排序调整而重新编号。

| US-A06 带凭据链接登录  | 作为使用者，我希望打开带 token 片段的访问链接就能登录，以便从终端或托盘把入口带到手机。       | 前端读取并保存 `#token=` 后立即移除地址栏和当前历史记录中的片段；片段不发送到服务器；WebSocket 认证通过子协议携带 token，不放入请求 URL 或 Cookie；链接仍是敏感入口。                                                                                                                                                                                                                                   |

## D. 终端操作、续接、多设备与生命周期

| 编号 / 功能                   | User story                                                                                         | 验收要点                                                                                                                                                                                                                                                                    |
| ----------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-D01 使用交互终端           | 作为使用者，我希望在浏览器里直接键入、查看彩色输出并操作全屏 TUI，以便像使用本地终端一样工作。     | 原始 PTY 字节送入 xterm；支持控制序列与终端尺寸适配；终端输出不被当作普通聊天文本重排。                                                                                                                                                                                     |

| US-O07 诊断 Windows 可达性         | 作为 Windows 使用者，我希望知道 WSL 内服务健康但 Windows 仍无法连接的情况，以便定位网络模式或 localhost 转发问题。                     | 独立从 Windows 回环地址检查可达性，不带 token 且不走系统代理；故障时提示 localhostForwarding/networkingMode；不把 WSL 内健康等同于 Windows 浏览器可达。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| US-O08 转发可信远程地址            | 作为 Windows 使用者，我希望在 NAT 模式下通过选定的主机地址访问 WSL 服务，以便从手机继续操作。                                          | 转发默认关闭，Tailscale 地址优先展示；仅服务健康、配置 token 且 Windows 可达时监听，条件失效暂停、恢复后继续；转发 HTTP 与 WebSocket 并校验地址对应 Host/Origin；保存地址选择并报告端口冲突，退出托盘即停止；不自动修改防火墙。                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| US-O09 打开和复制受保护入口        | 作为 Windows 使用者，我希望从托盘打开页面、复制本机/远程/公网链接或 token，以便把访问入口带到另一设备。                                | 操作时从 WSL 获取 token，不在 Windows 配置中保存；复制链接可带 `#token=`，不配置 token 时复制普通链接；敏感剪贴板排除历史和云同步，60 秒后仅在内容未被替换时清空；通知只显示无 token 地址。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| US-O10 退出托盘保留任务            | 作为 Windows 使用者，我希望只退出托盘而保留 WebMux，以便临时关闭桌面客户端却不中断任务。                                               | “仅退出托盘”不停止服务，重新打开后恢复可用控制；托盘转发随退出停止；Windows 注销或关机不承诺保留任务；需要停服务时使用单独停止操作。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| US-O11 判断 WSL 服务兼容与版本对应 | 作为 Windows 使用者，我希望托盘告诉我它与 WSL 中的 webmux 是否兼容、版本是否对应、该更新哪一边，以便两边分别升级后不再遇到含糊的失败。 | 托盘启动后首次取得状态、切换发行版或修改 `webmux` 路径、安装完成后，以及处于缺失或不兼容状态时打开菜单，在后台以 `version --json` 检查（旧版本回退文本并视为契约 v1），单次不超过 30 秒，日志记录两侧版本与契约；兼容只看控制契约，对应只比较版本号，`dev` 等非发布版本无法判断且不提示；结果只出现在菜单状态行，不发通知或弹窗：较旧一方、“比托盘新，请升级托盘”或“版本过旧，请升级”；WSL 较新且为发布版本时提供“下载托盘 <版本>”打开 Release 页面；契约不兼容仍可启动、停止、重启，以 Windows 侧可达性判断运行并显示“运行中（不兼容，功能受限）”，状态无法解析不判失败、不自动重启；缺少本机 API 时禁用启动；运行实例与已安装文件版本不同时提示重启后生效，只有托盘管理的实例可从菜单重启。 |

Windows 原生终端客户端复用 US-M01–US-M06：提供 run、attach、ls、open、status 与 version，服务仍在 WSL 中。发行版与 webmux 路径按命令行、环境变量、托盘设置、默认值依次解析；用 `wslpath` 换算盘符路径，识别同发行版的 WSL UNC 路径，无法换算时要求显式 Linux `--cwd`。经 `wsl.exe --exec webmux bridge` 连接，不依赖 localhost 转发；附着时使用 UTF-8/VT 控制台，恢复后还原模式与代码页。
